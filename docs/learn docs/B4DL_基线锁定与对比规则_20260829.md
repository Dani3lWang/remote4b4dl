### 2.2 冻结的评测命令（逐字，出自 `mllm/scripts/run_mixed_eval_after_train.sh`）

```bash
export HF_HUB_OFFLINE=1 HF_OFFLINE=1 TRANSFORMERS_OFFLINE=1
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
cd mllm && python3.10 -u evaluation/test_b4dl.py \
    --model_base ./base_model/vicuna-v1-5-7b \
    --pretrain_mm_mlp_adapter ./checkpoints/vtimellm-vicuna-v1-5-7b-stage1/mm_projector.bin \
    --stage2 ./checkpoints/vtimellm-vicuna-v1-5-7b-stage2-full-seqv3-mixed \
    --feat_folder ../encoders/lidarclip/b4dl/stage2_features \
    --test_data ./b4dl_dataset/test_qa.json \
    --ego_meta ./b4dl_dataset/ego_metadata.json \
    --frame_motion ./b4dl_dataset/ego_frame_motion.json \
    --sequence_metadata ../encoders/lidarclip/annotations/sequence_metadata.json \
    --per_sequence --answer_frames \
    --output <out>/predictions.json --metrics_output <out>/metrics.json
```

口径要点：`--per_sequence --frame_motion --sequence_metadata --answer_frames`（oracle 输入选择，GT 仅用于选输入帧/metatoken，不进 prompt）；`--dtype` 默认 float16；greedy 解码。

## 四、统计显著性阈值（判定"真改进"的标尺）

- **mIoU**：n=2,783，std 0.356，SE 0.00675 → 95% CI 半宽 **±0.0132**；bootstrap（3,000 次）[0.2568, 0.2832] 与解析式一致。
- **accuracy**：两任务等权平均，SE 0.00432 → 半宽 **±0.0085**。
- **文本指标**（BLEU/METEOR/ROUGE/BS）：未做逐样本 bootstrap，按跨版本经验波动取保守阈值 **≥0.01** 视为有意义。
- **判定规则**：
  - ΔmIoU > **+0.013** → 真改进；+0.005~0.013 → 存疑（需 TG 分布佐证，如唯一范围数/精确命中率）；< +0.005 → 噪声。
  - Δaccuracy > **±0.009** → 显著；否则不可区分。
- **语境校准**：与论文的 mIoU 差距 0.041 ≈ **3.1×** 95% 半宽（真差距，非噪声）；accuracy 与论文差 0.001 << 0.0085（统计上与论文持平）。下一改进档位即 mIoU ≥ **0.283**（B0 上限一个 CI 半宽）。

## 五、后续对比规则

1. **同口径原则**：新模型评测必须用 §2.2 命令原样执行（仅换 `--stage2` checkpoint 路径与输出目录）；数据文件 MD5 与 §2.1 一致才可与 B0 对比。
2. **追踪表**：每次新评测填入 §七 追踪表，附 ΔmIoU 与是否过显著阈值。
3. **基线重置条件**（触发任一即开新基线代号 B1、B2…，并在文档记录原因）：
   - 更换 LiDAR-CLIP 编码器或重新提取 `stage2_features`（特征语义变化，跨代不可比）；
   - 更换 stage1 projector 训练数据版本以外的 projector（如 162K 重训版——该变化本身就是被验证的变量，重训后先以同特征评测再决定是否升基线）；
   - 修改评测脚本 mIoU/指标计算逻辑或 `--answer_frames` 口径；
   - 测试集文件变化。
4. **oracle 口径声明保持**：所有对比沿用 `--answer_frames`（GT 恢复序列归属），报告与论文对比时必须带该声明（20260828 文档 §口径）。
5. **复现自检**：若对 B0 模型重跑 §2.2 命令，指标应与 §3.1 逐位一致（greedy 确定）；不一致 >1e-4 先查环境（GPU/driver/torch 版本）再怀疑代码。

## 六、B0 的已知边界（引用数值时须知）

1. **GPT-4o 缺失**：`predictions.json` 已含全部预测文本，配 API key 后可离线补算（无需重跑 2.5h 推理），补算后只增不改。
2. **BLEU-4 为 NLTK 实现**（method1 smoothing）：与 pycocoevalcap 实现存在已知虚高差异（见 `B4DL_评测方法学陷阱` 记忆/文档）；论文实现未披露，跨论文对比时以"同实现纵向对比"为准。
3. **BERTScore**：本地 roberta-large（避免 BERTScore OOM 与 HF 网络）；与论文 BERTScore 口径可能不同版本，仅纵向可比。
4. **oracle 输入选择**：TG 的 0.2696 是"正确序列输入下的定位能力"；论文是否同口径未披露，是 0.2696 vs 0.311 对比中唯一无法锁死的因素（实测口径影响 ±0.02）。
5. **138 条歧义归属**（4.96%）：已复核（08-29）——min-width 平局取最早序列、两侧代码一致、全量 mIoU 影响上限 +0.002（0.2696→0.2717），保持现状并声明，不构成基线缺陷。
