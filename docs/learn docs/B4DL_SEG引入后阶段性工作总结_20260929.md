## 0. 摘要（一页读）

这一阶段完成了从"B4DL 输出文本问答"到**"语言指令驱动的点级实例掩码"**的功能扩展，并建立了围绕数据、训练、推理、评测与故障定位的完整实验工具链。

1. **功能链路已实现并真实训练、推理过**：单帧点云 → 空间编码器（spconv U-Net）→ 场景 token → LM 路由（`<LOC>/<SEG>/<NOOBJ>`）→ 点级分割输出。
2. **一次有完整模型证据的有效改进**：训练 TF mIoU 从 **0.0075**（10 场景，完全记忆化）→ **0.0165**（200 场景）→ **0.1037**（空间编码器换代，**6.3×**），自由生成命中 1/330 → 22/330。
3. **瓶颈被系统性收窄**：七条常规杠杆（lr/dropout、场景数、语言侧、阈值、数据协议、编码器、损失）全部判死。最直白的一次定量是：**帧内同类只有一个实例时命中 30.2%，一旦有多个同类就塌到 4–7%，而排序 AUC 反而更高（0.914）** ⇒ 病灶是"不知道是哪一辆"，不是"不会分割"；oracle 探针 × 编码器微调 × 语义多任务 × 两档预算（20/30 ep）全部停在 **AUC 0.995–0.9976 平台** ⇒ **"单帧点特征撑不起实例接地"在当前结构下成立**。
4. **语义与实例可以共存**：多任务微调下线性语义探针 0.33109（+7.5% vs 预训练），否证了"实例微调必然伤语义"。
5. **当前处于选项 A（时序多帧）三臂的读数前夜**：A2（复制点对照）失效门通过并量出 test 侧噪声地板 ≈0.003；A1（补偿邻帧）19/20 轮已完成、dev 轴未买出信号（18/19 轮低于 A2），预计 09-30 01:30–02:00 出 test 单评；A3 排队。
6. **可靠性建设是重要产出**：修复了 NaN、推理占位符、验证 OOM、TF 分母漂移、in-range 索引错误、多帧坐标错误等；并沉淀了恢复契约、冒烟门、预注册判据等制度。

**尚未完成**：多帧效果验收（A1/A3 未出读数）；新编码器回接完整模型的最终自由生成评估；独立 holdout、多 seed、负例拒识与 B3 回归。

### 3.2 低 mIoU 是怎么被逐层归因的（现象 → 证据 → 对策 → 结果）

| 现象 | 诊断证据 | 对策 | 结果 |
|---|---|---|---|
| 首训 best 仅 0.0075，一度被读成"val mIoU≈0" | mini 只有 10 场景 ⇒ 完全记忆化；`--validation-samples` 默认 32 ⇒ 单场景探针假象；末步 total loss 1.336、`mask_seg` 0.860（并非"全归零"） | 扩到 200 场景 + `--validation-samples 0` 全量 TF | 0.0165（9.4×），同时排除"数据规模是唯一瓶颈" |
| 文本分支很快拟合、掩码分支不动 | 控制臂 9300 step：`mask_seg` mean 0.658 / p50 0.803，仅 **10.8%** 的 step seg loss < 0.05；自由生成 `text.exact_match_rate = 1.0` | 判定病灶在掩码侧，停止在语言侧加杠杆 | 语言侧三臂后来确实全负 |
| mIoU 卡在 0.0165 | 旧空间编码器只训过 1 epoch，lidarseg 历史 mIoU 0.1244 | FP32 重做空间语义预训练（bf16 触发 spconv NaN ⇒ 只能 encoder fp32 分精度）⇒ 换代 tvenc | **0.1037 = 6.3×**；自由生成 1/330 → 22/330 |
| 命中 <10%、大量空掩码 | 预测掩码中位 **3 点** vs GT 11；空掩码 140/330；`recall_random_k = 0`（随机取 K 点从不命中） | 查明**沉默塌缩**：正例率 3.2e-4 ⇒ 逐点 BCE 稀释 ~3000×，"沉默"与"对冲"损失只差 4.9% ⇒ 上 balanced BCE / Tversky | balanced 过分割被护栏否决；Tversky 把尺寸修到 12 vs 11 |
| 尺寸修好了，命中还是不动 | Tversky 20 ep：hit 仍 **24/330**（与对照逐位相同），第一大失败模式变成 `right_class_wrong_place`（87→102） | 判定为**实例接地失败** ⇒ 转 oracle 探针定位（§3.9） | 七条杠杆全部判死 |
| oracle 也只停在 AUC 0.995 带 | 两种机制 × 两档预算全在 0.995–0.9976；30 ep 延长使缺口反扩到 16.9× | 唯一未攻击的假设 = "单帧" ⇒ 时序三臂（§3.11/3.12） | 进行中 |

| **新空间编码器（tvenc）** | **22/330** | **6.667%** | 0.22876 | 0.08812 |
| 扩场景（tvenc680） | 28/330 | 8.485% | 0.22597 | 0.10085 |
| internal679 | 24/330 | 7.273% | 0.23690 | 0.09069 |

编码器换代收益明确；扩场景 +6 命中是积极信号，但无多 seed/独立测试，**不能断言统计显著**；命中按类别无关 IoU 计算，类别正确性需另行报告。

### 3.4 自由生成失败分解（同 300 条 / 330 GT 目标）

| 失败标签 | internal679（对照） | Tversky-ext20 | tvenc680 |
|---|---:|---:|---:|
| hit（IoU≥0.5） | 24 | 24 | **28** |
| `predicted_mask_empty` | **140** | 99 | 136 |
| `near_miss_below_0.5` | 71 | 100 | 80 |
| `right_class_wrong_place` | 87 | **102** | 77 |
| `wrong_class_wrong_place` | 7 | 5 | 8 |
| `overlap_stolen_by_other_target` | 1 | 0 | 1 |
| 预测掩码中位点数（GT 12） | **3.0** | 11.5 | 3.0 |
| 零掩码目标数 / 330 | 142 | 103 | 143 |

- 匹配 IoU 直方图（对照）：[0,0.1) **257**、[0.1,0.2) 21、[0.2,0.3) 8、[0.3,0.4) 12、[0.4,0.5) 8、[0.5,0.7) 14、[0.7,1.0] 10 ⇒ 失败不是"差一点"，而是**塌到 0 或干脆命中**的双峰。Tversky 只把空掩码搬进 near-miss 与"类对地方错"两个桶，**hit 一个没多**。
- 按类别（对照）：**bus 8/13 = 61.5%**、truck 6/42 = 14.3%、car 9/132 = 6.8%、traffic_cone 1/19 = 5.3%，而 **pedestrian 0/55、barrier 0/41、construction_vehicle 0/12、bicycle 0/11、motorcycle 0/5 全灭** ⇒ 命中几乎全在大尺寸类上，正例点数直接决定成败。
- 按语言线索（对照）：无序数 22/165 = 13.3%、序数 2–3 桶 2/83 = 2.4%、**序数 4–9 桶 0/66、10+ 桶 0/16 全灭**；左 6/134、右 9/145。
- `text.exact_match_rate = 1.0`（生成的答案文本与 GT 完全一致）⇒ **语言侧已饱和**，失败全在掩码侧。`class_macro_f1 = 1.0` 只统计成功匹配的子集，不是整体分类 F1，勿引用。

### 3.5 决定性的一次定量：帧内有几个同类实例（in-range 接地诊断，n=1038）

| 帧内同类实例数 | 物体数 | AUC（排序质量） | recall@0.5 | Tversky 臂 recall |
|---|---:|---:|---:|---:|
| 1（无实例歧义） | 159 | 0.8602 | **0.3019** | 0.2453 |
| 2–3 | 180 | 0.7872 | 0.0611 | 0.0667 |
| 4–7 | 189 | 0.8692 | 0.0688 | 0.0741 |
| 8+ | 510 | **0.9138** | **0.0392** | 0.0392 |

⇒ **同类只有一个时命中 30.2%，一旦有多个同类就塌到 4–7%；而 AUC 在"8+ 同类"时反而最高（0.914）** —— 模型非常会判断"这些点是不是该类的点"，完全不会判断"是哪一辆"。序数桶同样反常：序数 4–9 的 AUC 全场最高（0.9217）而 recall 仅 0.0090，序数 10+ 直接 0/100。这是整条 seg 线对"实例接地失败"最直白的定量，也是后续所有杠杆（损失/阈值/先验）都不动 headline 的原因。

## 5. 判据与方法学自身的错误（换轴与纠偏）

| 错误 | 纠正 |
|---|---|
| **判据挑错轴 ×3**：一直拿 `recall@0.5` 当判别量（正例 3e-4 下天然无效） | 换 AUC + `recall_top_k`（免幅值）；阈值用先验推导（1−K/N），不拟合观测；看过数据后改判据须显式声明 |
| 预注册没给"优于最好预期"留档（多任务 miou +7.5% 无档可接） | AND 条件须注明主/次容差；显式包含"超预期"档 |
| 度量 bug 偏差方向判反（前缀掩码曾被说成抬高 AUC，实测为压低） | 预测偏差方向时分子分母两侧效果都要算全 |
| 同 seed ≠ 同轨迹（30 ep 延长跑 ep0 结束 dev AUC 已差 6.1e-3） | 启动检查加逐轮指标比对；此类延长改称"同分布复现" |
| 汇总脚本基线标签互换（打印 +50.2%，真值 +7.5%） | 基线变量名带来源；判据阈值不得与含混变量绑定 |
| 早停 manifest 乐观偏差（+0.0143 → held-out 仅 +0.0067 且 recall 转负） | 裁定一律走 held-out；早停 manifest 只用于选轮 |
| "平台"容差 0.0015 在噪声之内（A2 空对照极差都有 0.0026） | 平台结论靠"停在 0.995–0.9976 带"的量级判断，不靠极差阈值 |
| 2026-09-28 审计修订 | "AUC≥1−K/N 才可能 top-K"**非必要条件**（偏斜排序反例）；"单帧点特征不可能接地"改为"当前结构/预算/协议下仍弱" |
