## 3. 模型结果应该怎样理解

### 3.1 Phase 2.2 的损失消融

TF 列来自各自训练日志的旧分母口径，用于记录实验过程。接地诊断列来自 val_thin 前 1000 条记录、1068 个被诊断目标，和自由生成指标分开报告。

| 实验 | 损失配置 | 4-epoch TF mean IoU（历史值） | 接地 AUC | 接地 recall@0.5 | 预测掩码中位点数 / GT |
|---|---|---:|---:|---:|---:|
| A1 | balanced BCE + Dice | 0.06150 | 0.94532 | 0.02154 | 1712.5 / 11 |
| A2 | plain BCE + Tversky(0.3, 0.7) | 0.12546 | 0.91674 | 0.07772 | 14 / 11 |
| A3 | balanced BCE + Tversky | 0.06530 | 0.94721 | 0.02341 | 1500 / 11 |

A1/A3 说明“正例概率或 AUC 升高”本身并不等于可用的分割。预测范围过大，会让实例 IoU 和硬命中数下降。A2 在这组实验里主要解决了尺寸校准问题。

Phase 2.1 的推理侧去先验实验也呈现同一现象：AUC 从 0.85757 升到 0.91653，但预测尺寸从 3 点变为 63 点，recall 从 0.08614 降到 0.04307。单看排序指标会得出过于乐观的结论。

### 3.4 Oracle 探针能说明什么

首轮 B0 使用冻结点编码器，并训练由 GT 中心和类别生成 query 的小网络及 mask decoder。训练 loss 为：

`0.92334 → 0.81457 → 0.77842 → 1.02735`

末轮明显反弹，当时又只评估末轮。test 端 AUC=0.97762、recall=28/623、预测尺寸中位数=37 点、GT=11 点，尚不能把低 recall 单独归因于点编码器。

已于 18:22 启动的 v2 配置为 6 epochs、学习率降到 1e-4、每轮洗牌和 dev 评测、按 dev mean IoU 选轮次、补 GT-size top-K，并只在选定轮次上评一次 test。它解决了首轮的部分训练与选轮问题，但仍需注意：

- 该探针使用 GT 位置信息，属于带额外信息的诊断；有限训练得到的分数不是严格的模型容量上界。
- oracle 与完整模型的 decoder 权重、训练方式、评测样本数不同；直接比较 AUC 差值，不能把全部差距归因于语言模型。
- 代码注释用 `AUC >= 1-K/N` 推导 top-K 成功条件，这不是充分或必要条件。AUC 是全局正负样本对排序平均值，不能唯一决定最前面 K 个点的纯度。例如 N=32500、K=11，若 8 个负点排在全部正点之前，其余负点在后，AUC 仍约为 0.99975，但 top-11 仅有 3 个正点，IoU=3/19≈0.158。
- 因此应直接读取同样本的 top-K IoU/recall、Precision@K 和尺寸误差，并结合训练拟合程度判断瓶颈；不能仅按 AUC 的固定区间决定换编码器。

### 4.2 范围过滤与分母修正

原始 val_thin 的 2440 个目标中，有 143 个完全位于编码器范围之外。修正后的未过滤 TF 只对 2297 个可评分目标计算指标。

过滤器按整条记录删除，保证 query、answer 和目标列表仍一致。它删除了 140 条记录，留下 2108 条、2278 个目标；因此除了 143 个不可达目标，还随整条多目标记录移除了 19 个可达目标。这个差额有明确的数据原因。reachable 的成绩必须和同一 reachable 清单上的对照比较。

原始集与 reachable 集应同时报告，并公开被删除的记录/目标数、部分越界目标和类别分布，避免通过删除难例制造不可比的提升。

### 4.3 尚未闭合的评测能力

- **负例覆盖不足。** 训练集和 val_thin 都无负例。评测代码在负例数为 0 时仍可返回误报率 0；应标为 N/A，并在有负例的内部清单上补测。
- **类别 F1 的范围有限。** 远端 metrics.py 仅把 IoU 达标的匹配写入类别混淆矩阵，低 IoU 和未匹配目标没有进入各类别 FP/FN。当前 class_macro_f1=1.0 不能视为全任务识别 F1。
- **尚无断点恢复的完整评测流程。** 当前 evaluate_reasonseg.py 没有 resume 参数，逐条保存掩码，但 predictions.json 和 metrics.json 在循环结束后才写入。不能承诺中断后自动跳过已完成记录。
- **缺少最终全量证据。** 当前用于主要结论的自由生成仍是 300 条子集；B1 的接地诊断和 TF 复算不等于自由生成评测。
- **B3 保持情况仍需回归验证。** checkpoint 记录的 B3 fingerprint 一致说明来源一致，不能替代原有问答任务的回归成绩。

### 下一轮训练的决策顺序

1. **先看 oracle 是否能在少量训练样本上拟合。** 若连训练样本也不能稳定拟合，先检查点与标签映射、in-range 索引、损失及优化设置；此时扩大主模型训练预算意义有限。
2. **若 oracle 在固定内部 dev 上明显优于完整模型，优先做实例查询方向的单因素实验。** 候选包括 query 的位置/实例对比监督，以及同类、多实例、序数查询的监督设计。先选一项，避免同时更换查询数量、损失和解码器。
3. **若 oracle 已能拟合训练样本，但在相同内部 dev 上 top-K 仍弱，再研究点特征和空间分辨率。** 先分析小目标、距离和类别分层，再选择多尺度或 voxel_size 实验；记录 GPU 显存与推理成本。
4. **B1 先保留为诊断支线。** 现有 AUC、尺寸和召回均未达到原 PASS 条件，不直接启动 20-epoch 扩跑。若后续同口径自由生成证明有明确收益，再按同调度预算复核。
5. **下一轮训练纳入真实负例。** 固定负例采样策略并单独报告 NOOBJ 误报，避免只在正例上学习和选模型。
