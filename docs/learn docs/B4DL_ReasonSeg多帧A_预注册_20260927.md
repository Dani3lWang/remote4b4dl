# 选项 A：引入时序多帧 —— 预注册（2026-09-27，跑之前写死，不看数据不改）

前置裁定链见 `docs/memory/b4dl-reasonseg-seg-line-2026-09.md`：七条杠杆判死 + oracle 探针三机制（冻结 / 真微调 / 多任务）× 两档预算（20 / 30 epoch）全部停在 **AUC 0.995–0.9976** ⇒ "单帧点特征撑不起实例接地"定案。A 是剩下唯一还没被攻击的假设：**"单帧"这三个字**。

## 1. 先记下四个约束（都是今天实测/读码得到的，不是假设）

1. **掩码不是 3D 框内点**。逐点掩码 = nuScenes panoptic 的 `instance_index == target.panoptic_id`（`mllm/vtimellm/segmentation/data.py:104`），manifest 里连 `center` 都没落盘（`scripts/build_reasonseg_nuscenes.py:293-295`）。⇒ 判据里那个 **N≈32,530 是"帧内落在 `point_cloud_range` 里的点数"中位数**，不是框内点数。历史文档/报告里"框内点"的措辞是错的，**数字与判据不受影响**（N 就是参与打分的点数），本节起统一改称"range 内点"。
2. **编码器输入契约不可动**。`SparseUNetPointEncoder._voxelize` 对同体素点做均值（`spatial_encoder.py:173-179`），且 `load_spatial_encoder_checkpoint` 校验 `voxel_size`/`point_cloud_range` 并 `strict=True`（`checkpoint.py:169-182`）⇒ 加"时间/帧号"通道要重做空间预训练，本轮**不做**。多帧只能在**点云层面**拼接，输入仍是 `x,y,z,reflectance` 4 列。
3. **只有 2 Hz**。`samples/LIDAR_TOP` 34,149 = 全部关键帧，邻帧相隔 **0.5 s**；`sweeps/LIDAR_TOP` 盘上只有 3,531 个文件，补全 10 Hz 需 ~205k 文件 ≈ 230 G，而实例盘剩 71 G ⇒ **不可行**。A 的一切结论只在"0.5 s 间隔"这个条件下成立，报告里必须写。
4. **跨帧同实例只能靠标注跟踪**。panoptic npz 只有 `data` 一个键、`%1000` 是帧内实例号 ⇒ 无跨帧身份。可行路径是 `sample_annotation.json` + `instance_token`（仓库里已有先例：`datageneration/generate_description.py:245-251,338-349` 按 `instance_token` 聚合跨帧轨迹、`mllm/vtimellm/lidar_visualizer.py:376-399` 沿 `sample_annotation["prev"]` 回溯）。刚体变换复用 `lidar_visualizer.py:152-187` / `encoders/lidarclip/lidarclip/loader.py:166-176`（`ego_pose.json`、`calibrated_sensor.json` 都在盘上）。

## 2. 三臂设计（A2 的定义是关键修正）

设 F = 帧数（含 anchor），anchor = 记录自身那一帧。

| 臂 | 点云怎么来 | 掩码怎么来 | 它隔离出什么 |
|---|---|---|---|
| **A1 真时序** | anchor ± Δt 的邻帧点，经 `ego_pose`+`calibrated_sensor` **补偿到 anchor 系**后并集 | anchor 目标实例 **+** 邻帧中 `instance_token` 相同的同实例点 | 主臂：几何对齐后的新信息能不能打破平台 |
| **A2 密度对照** | **把 anchor 帧自己的点复制 F 份** | anchor 掩码复制 F 份（同实例点重合） | 把"N 变大 / 体素变满 / 门槛随 K、N 漂移"这些纯数量效应扣掉 |
| **A3 不补偿拼接** | 邻帧点直接并入，**不做 ego 补偿** | 同 A1 | 在 0.5 s 间隔下，"米级错位的点更多"值多少 —— 防止把 A1 的收益误读成"点更多" |

⚠ **A2 不能写成"不补偿的多帧拼接"**（我最初的提法是错的）：0.5 s 下不补偿拼接引入的是错位噪声而非中性的密度增量，那样 A2 会被系统性地压低，A1>A2 就说不清是"对齐"还是"信息"。A2 用复制点 ⇒ 同体素均值不变 ⇒ **严格零新信息**，并且它带一个**可证伪的预言**：A2 的逐点 AUC 应当 ≈ 单帧水平（0.9938–0.9958 带内）。A2 若显著偏离该带，说明拼接/复制本身改变了度量，A1 的读数作废，先修度量再谈结论。

## 3. 门槛必须按臂重算，不许沿用 0.99963

先验门槛 = `1 − K/N`（top-K 命中所需，K = 正点数中位、N = 参与打分的点数）。

- **A2**：K、N 同乘 F ⇒ 比值不变 ⇒ 门槛仍是 **0.99963**（这正是它作对照的意义）。
- **A1 / A3**：N ≈ F×32,530，K = 跨帧同实例点并集，**增长不是线性**（0.5 s 内同一物体的点集部分重叠）⇒ 门槛必须**实测 K、N 后重算并写进报告**，跑之前先验推导只能给区间：F=3 且 K 增长 1.6–2.0× ⇒ 门槛约 **0.99912–0.99938**；F=5 同理另算。⇒ **A1 的绝对 AUC 允许低于 A2，只要它离自己的门槛更近**。判据一律用"**距本臂门槛的倍数**"，不用裸 AUC 横比。

## 4. 预注册判据（主轴 = 距本臂门槛的倍数；次轴 = R@0.5 / top_K / IoU / 尺寸比；两轴分离时分开陈述）

参照：单帧多任务 30ep = test AUC 0.99377、距门槛 **16.9×**；20ep = 0.99575、**11.5×**。

| 档 | 条件 | 结论与下一步 |
|---|---|---|
| **A-a 推翻** | A1 距门槛 ≤ 3× | top-K 有救，A 升为主攻，立刻进完整模型联合训练 |
| **A-b 实质逼近但未达** | A1 距门槛 3–8× 且 A1 的 R@0.5 ≥ 0.40 | "单帧"确实是瓶颈之一，但 0.5 s 稀疏度不够 ⇒ 报"受限采样下部分成立"，下一步讨论是否腾盘做 10 Hz |
| **A-c 优于 A2 但排序不动** | A1 距门槛 ≥ 10× 但 R@0.5/top_K 明显高于 A2 | **两轴分离**：多帧只改善幅值/召回，不改善排序 ⇒ 与 C 同构，写进"第 N 次幅值≠排序"，转 D |
| **A-d 平台普适** | A1 与 A2 距门槛同量级（比值 < 1.5×）且 A2 落在单帧带内（预言成立） | **点级表示层面无法接地，与时序无关** ⇒ 定案，转 D 写负结果 |
| **A-e 劣于预期** | A1 比 A2 更差 | 0.5 s 错位代价高于新信息收益 ⇒ 只报"该采样密度下多帧为负收益"，**不得**外推成"多帧无用"；A3 用来确认这个解释 |
| **失效门** | A2 显著偏离单帧带（预言破） | 度量被拼接改变，本轮全部读数作废，先修度量 |

另外三条硬规定：① **必须同时报 A1/A2 两臂**才允许下任何结论（单臂不裁定）；② A3 若来不及跑，报告里显式写"未隔离错位效应"，不许用 A1>A2 直接声称"时序有用"；③ 掩码构造改动必须有冒烟中止门（跨帧同实例点数、补偿前后质心位移、F 帧拼接后的 K/N 分布，跑之前先看这三个数对不对）。

## 5. 成本与顺序

实测单帧 20ep ≈ 8.7 h、30ep ≈ 12.9 h（26 min/轮）。拼接后 N×F ⇒ 逐点 memory 展开 `[物体数, N, 256]`（`heads.py:57-64`）是显存闸门，F=3 时单轮预计 ×2 以上 ⇒ **先跑 F=3、20 epoch、batch 视显存降半**，A1/A2 两臂合计预算 **25–35 h 串行**。执行序：冒烟数核验 → A2（便宜、且是失效门）→ A1 → 视结果决定 A3。

## 6. 冒烟门实测（09-27 16:20，`smoke_multiframe.py`，CPU）—— 已全过，并抓出两个真 bug

三张清单各 60–80 条，`--num-frames 3`：

| 清单 | 框 vs GT 掩码 IoU 中位 | 跨帧新增正例中位 | 单帧 K/N/门槛 | a1 K/N/门槛 | a2 K/N/门槛 | a1-a3 掩码不一致 |
|---|---|---|---|---|---|---|
| `val_thin`（test，裁定用） | 1.0 | 23 | 13 / 32,412 / **0.999599** | 41 / 97,287 / **0.999579** | 37.5 / 97,236 / 0.999599 | 0 |
| `train_internal679x11` | 1.0 | 21 | 12.5 / 32,441 / 0.999615 | 33.5 / 97,323 / 0.999656 | 37.5 / 97,324 / 0.999615 | 0 |
| `val_internal_es`（dev） | 1.0 | 18 | 18 / 32,375 / 0.999444 | 40.5 / 64,422 / 0.999371 | 54 / 97,125 / 0.999444 | 0 |

**先验门槛自证**：单帧在 `val_thin` 上量到 0.999599，与 §3 事前推导的 0.99963（K=12、N=32,530）吻合 ⇒ 装配口径没跑偏。
**a2 的门槛与单帧逐位相等**（差 0.0）⇒ "复制 F 份不改变 1−K/N"这个设计前提成立，它可以当失效门用。

**冒烟门抓出的两个 bug（都在这一步之前会烧掉 25–35 h）**：

1. **3D 框的半尺寸轴序错**：nuScenes `sample_annotation["size"]` 是 **(width, length, height)**，而框的局部 x 轴沿 **length**（`nuscenes/utils/data_classes.py:613-615`：`x_corners = l/2`、`y_corners = w/2`）。按数组原序除二 ⇒ 一辆 4.6×1.9 的车变成"长 1.9、宽 4.6"，框与 GT 掩码 IoU 中位 **0.0**、跨帧正例全 0。
2. **点云在 LiDAR 传感器系，不在 ego 系**：只读 `ego_pose` 不读 `calibrated_sensor` ⇒ 框相对点整体偏了 LIDAR_TOP 的 ~(0.94, 0, 1.84) m 加约 90° 偏航，IoU 仍为 0。修法是把每帧的"系"定义为**该帧的 LiDAR 传感器系**（`to_global = R_ego @ R_cs`、`origin = t_ego + R_ego @ t_cs`）——这样 anchor 段与单帧跑喂进编码器的张量**逐位相同**，"唯一变量是多了邻帧"这个前提才守得住。

**另一个与 A 无关但要记的事实**：`reasonseg_val_internal_es.jsonl`（dev/早停集）**94% 的记录落在各自场景的首帧**（200 条抽样 189 条），所以 dev 上只能拼到"未来一帧" ⇒ `frames_used` 中位 2、dev 的 N（64k）比 train/test（97k）小三分之一。DB 本身没问题（34,149 样本中 prev 为空的恰好 850 = 场景数）。⇒ **dev 与 test 的门槛必须分开算，选轮只按 dev、裁定只按 test**（沿用既有纪律），但两轴的绝对 AUC 不可跨 split 比。

**点火前的最后一条规定**：a1/a3 的 K 从 13 涨到 41（3.2×）而 N 涨 3.0× ⇒ 门槛几乎不动（0.999599 → 0.999579）。所以裁定表里的"倍数"用**各臂自己的门槛**（上表右三列），不得拿 a1 的裸 AUC 去比单帧的 0.99377。

**跑前补记（09-27 17:35）**：A 三臂一律用 `--require-reachable` **关闭**的语义。原因：`4819a15` 把实例侧 train 的 `require_reachable` 硬编码成 True，但盘上没有过滤过的 train 清单（只有 `reasonseg_val_thin_reachable.jsonl`），实测第一条不可达目标就抛错；而 20/30ep 单帧参照用的是合并前的代码。已把它改成旗标（默认关），以保持"唯一变量 = 实例侧帧装配"。若将来要按新语义跑，必须先产出 audited train 清单**并把单帧参照一起重算**，否则跨跑不可比。

## 7. 噪声地板实测（09-28 13:20，A2 跑到 ep16 时补写，**早于 A1 的任何读数**）

a2_repeat 与单帧参照比，唯一差异是"同一帧的点被复制 3 份"——按构造零新信息。16 轮实测：

- dev AUC 逐轮贴合单帧：|Δ| 典型 **0.0005**、最大 **0.0018**（ep15，a2 0.99462 vs 单帧 0.99642）；ep1–14 全部落在单帧 ep8–19 带 [0.99591, 0.99748] 内 ⇒ **失效门预言成立**（复制点不改变排序质量）。
- dev `recall@0.5` 与 `iou_mean` 与单帧同量级（0.22–0.28 vs 0.18–0.29）⇒ IoU 对"三份集合 vs 三份 GT"是尺度不变的，a2 确实是干净的空对照。
- **尺寸中位 42–219 vs 单帧 11–56** 是点被复制 3 份的恒等结果，**不得读成过触发**。⇒ 幅值轴的绝对值只在同臂内可比，跨臂只能比"与本臂参照的相对位移"。

**由此钉死两条判据闸门（A1/A3 读数前生效）**：

1. **分辨力门槛**：a2 与单帧同数据不同排列都能摆动到 ±0.002 dev AUC ⇒ **A1 相对 A2 的 dev AUC 优势必须 > 0.002 才算信号**；小于它一律记"与噪声不可分"，不得写成"改善"。test 侧同理，须同时报"距本臂门槛的倍数"并检查该倍数之差是否超出同量级的 run-to-run 摆动。
2. **失效门自动闸**：a2 最终 test AUC 若掉出单帧四跑覆盖的带 [0.99038, 0.99760]，说明拼接本身改变了度量 ⇒ **不启动 A1/A3**，先修度量。串行链已按这条实现（`chain_three_arms.sh`）。

## 8. A2 实测（09-28 16:52，rc=0）：失效门通过，并量出 **test 侧噪声地板**

a2_repeat 20 轮，选定 ep19，`dW conv` 21.99%。test = `val_thin` 416 物体 + 23 不可达：

| | 单帧 20ep | 单帧 30ep | **a2_repeat F=3** |
|---|---|---|---|
| test AUC | 0.99575 | 0.99377 | **0.99296** |
| 距本臂门槛 | 10.6x | 15.5x | **17.6x** |
| R@0.5 / topK / IoU | 0.2644 / 0.3197 / 0.2991 | 0.2692 / 0.3582 / 0.3122 | 0.2404 / 0.3149 / 0.2818 |
| 尺寸 pred/target | 28 / 12 | 27.5 / 12 | **79.5 / 36.0**（= 3x 恒等） |
| dev 末 8 轮极差 | 0.00138 | 0.00138 | **0.00260** |

1. **失效门按预注册判据通过**：a2 的 test AUC 0.99296 落在单帧四跑覆盖带 [0.99038, 0.99760] 内，且 topK/IoU/R@0.5 与单帧同量级、尺寸严格 3x（复制的恒等效应，不是过触发）⇒ 拼接/复制本身没有改变度量，**A1/A3 的读数可信**。
2. **但 a2 送出一个比预期更重要的副产品：test 侧的噪声地板远宽于 dev 侧。** a2 与单帧 20ep **信息完全相同**（复制不带来任何新点），test AUC 却低 0.0028、缺口从 10.6x 变成 17.6x；dev 末 8 轮极差也从 0.00138 涨到 0.00260。⇒ **新增两条闸门（在 A1 的 test 数出来之前生效）**：
   - **A1 的 test AUC 必须比 a2 高 > 0.003**（等价于"距门槛倍数"缩小 > 1.7x）才算信号；小于它一律记"与 run-to-run 摆动不可分"，不得写成时序收益。
   - **test 只评一次是这条程序里最薄的地方**：dev 有 20 个读数可以估噪声，test 只有 1 个。若 A1 与 a2 的 test 差落在 0.003 以内，正确结论是"本设计分辨不出"，而不是"略有改善"。
3. **另一条与"平台"判据有关的观察**：a2 的 dev 末 8 轮极差 0.00260 已经超出 C 阶段用来认定"平台"的 0.0015 容差，而它明明是与单帧同信息的空对照 ⇒ **0.0015 这个容差本身在噪声之内**，今后引用"平台"结论时要说清这一点：平台的成立靠的是"AUC 停在 0.995-0.9976 这条带里"这个量级判断，不是靠极差阈值。

### 裁定：落 **A-e（劣于预期）**，且我事前给 A-e 写的机制解释被数据推翻

1. **A1 是三臂里最差的**，比空对照 a2 低 **0.00566** AUC、比不对齐的 a3 低 **0.00358** —— 两个差都越过 §8 钉死的 0.003 test 噪声地板 ⇒ **可分辨的负信号**，不是摆动。dev 侧同向（a1 末 8 轮 0.9938–0.9961，明显低于单帧/a2/a3 的 0.9958–0.9976）。
2. **撤回 A-e 档原文的解释**："0.5 s 错位代价高于新信息收益"。实测**不对齐（a3）反而优于对齐（a1）**，所以负效应不来自"没对齐"，而来自"对齐这件事本身"。档位命中没错，机制标签错了 —— 与 §8 第 5 行的教训同源：**分支表能覆盖结果，不等于事先想对了因果**。
3. **候选机制（标注为未证）**：编码器对**同体素点取均值**且**没有时间/帧号通道**（这是当初为守住 voxel 契约、避免重做空间预训练而接受的约束）。ego 补偿后，**静止背景**的三帧点落进同一体素 ⇒ 均值不变；**运动物体**不同时刻的点落进同一体素 ⇒ **均值把物体自身的时变信号抹平**。于是 a1 实际测的不是"时序建模能不能帮忙"，而是"**无时间通道的体素均值聚合**能不能帮忙"——后者被判定为**负**。
4. **因此本实验的边界必须写清楚**：
   - 可以写："在现有编码器契约（体素均值、无时间通道、2 Hz 关键帧）下，多帧拼接使逐点排序质量下降 0.0057 AUC，缺口从 17.6× 恶化到 30.1×，且对齐比不对齐更差。"
   - **不可以写**："时序/多帧不是杠杆" —— 这个结论没有被测试过，它需要时间通道才谈得上。
5. **副作用记录**：a3 的选定轮是 **ep14（中间）**，a1/a2 仍是 **ep19（末轮）**；a3 的 dev 极差只有 0.00092（三臂里最平）。尺寸轴跨臂仍只能读相对位移（a2 的 79.5/36 与单帧的 28/12 是同一次过触发的 3× 恒等像）。

### 下一步只剩两个，且代价不对等

- **A′：给编码器加时间通道** ⇒ 会改 `input_dim`、撞 `checkpoint.py:169-182` 的 strict 与 voxel 契约校验 ⇒ **必须重做空间预训练**（此前那轮约 12 epoch / 数小时，加 ReasonSeg 侧三臂又是一轮 87 h 量级）。**代价远高于 A 本身**，且即便做了，0.5 s 的关键帧间隔仍在（要 10 Hz 得再腾 230 G 盘）。
- **D：收口写负结果** ⇒ 材料已齐：八条杠杆判死（含机制）+ 瓶颈定位到排序幅值两轴 + 三机制（冻结/真微调/多任务）× 两预算（20/30 轮）× 三臂对照（单帧/空对照/不对齐/对齐），外加**自测的噪声地板**（dev ±0.002、test 0.003）作为这类消融的可分辨极限。

判断：A′ 的期望收益要在"重做预训练 + 扩盘 + 87 h"之后才可能出现，而 A 已经证明**在当前契约下对齐是负效应**；除非愿意把项目重心移到表示层重构，否则**走 D**，把 A′ 记为"需要新契约才有资格谈"的后续工作。
