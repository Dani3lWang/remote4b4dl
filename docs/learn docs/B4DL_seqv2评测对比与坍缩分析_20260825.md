## 三、根因与对策（seqv3 方案）

根因：发布的 benchmark 丢失了每条 QA 的**序列归属**字段（官方 test 分文件同样没有），
导致 TG 这类问题文本无帧号的任务只能喂整 scene；而论文输入 S_L 是序列（5-19 帧），
每条 QA 都从某个具体序列生成。实测序列归属可从 GT 答案帧范围 100% 恢复：

- test TG 2783 条：2645 唯一归属 + 138 歧义 + 0 无归属
- 89% 的 GT 范围精确等于序列边界（(6,14) = 序列 [6,8,10,12,14] 首末帧）
- 论文 Appendix C："metatoken 描述 QA pair 中引用的首末帧"——对 TG 而言引用帧在答案里

对策（seqv3，全部在论文方法框架内）：
1. 训练/评测双侧对无帧号问题回退解析 GT 答案帧范围 → 恢复包含序列 → 输入改为
   序列精确采样帧（feat_indices）+ 按引用范围渲染真实帧 metatoken。
   评测侧用 GT 恢复归属属于还原论文原始评测设置（官方 test 项本就带序列归属），
   报告中如实声明。
2. stage1 projector 用 95,048 条 nu-caption（论文用 162K，旧 projector 仅用 699 条
   训练）重训后，再训 stage2 seqv3。

预期：序列级输入下即使模型坍缩为"输出整个输入序列"，mIoU 也远高于 0.184
（89% 的 GT 就是序列边界，IoU=1）；论文 0.311 对应序列内定位不完美的模型。
