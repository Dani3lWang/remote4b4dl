## 一、这个仓库是什么

对论文 **B4DL: A Benchmark for 4D LiDAR LLM in Spatio-Temporal Understanding**（ACM MM 2025）的**独立复现**。一句话概括：把 nuScenes 自动驾驶数据集的 **4D LiDAR 点云**（3D 空间 + 时间序列）变成"编码器特征 + 问答数据"，再喂给一个 **多模态大语言模型**（Vicuna-7B），训练它回答关于驾驶场景时空理解的问题（"前方是否有行人？""第 3 到第 7 帧发生了什么？"）。

三大模块与数据流：

```
nuScenes 数据集（6 相机图像 + LiDAR 点云 + 标定/元数据）
  │
  ├─ [datageneration/]   相机图 → GPT-4o → 场景描述 JSON → 6 类任务 QA 对话 JSON
  │                      （数据是"老师"：由 GPT-4o 生成、人工格式化成 Vicuna 对话格式）
  │
  ├─ [encoders/lidarclip/]  点云 → SST 稀疏 Transformer 编码 → AttentionPool → 768 维向量
  │                      （CLIP 对齐：让点云特征与 CLIP 文本空间对齐，MSE 损失，Lightning 训练）
  │                      Stage1 特征：每帧一个 (1, 768)；Stage2 特征：每场景拼接 (N_frames, 768)
  │
  └─ [mllm/]             特征 + QA 数据 → VTimeLLM 三阶段训练 → 六任务评测
                         （<video> 占位 token 被替换为投影后的点云特征；LoRA + DeepSpeed ZeRO-3）
```

六个 QA 任务：简单类 `existence` / `binary` / `time_grounding`，复杂类 `description` / `temporal_understanding` / `comprehensive`。评测指标：accuracy、mIoU、R@n、CIDEr、METEOR、BLEU、BERTScore、ROUGE-L。

**学习这个仓库 = 同时学习四个领域的交叉**：多模态大模型（LLM + 视觉 token 注入）、3D 点云感知（SST/BEV）、大模型训练工程（LoRA/DeepSpeed/多阶段课程）、LLM 数据工程（GPT 生成 + 质量控制）。

按"必须 / 建议 / 按需"三档。每条附**自检问题**——答不上来就先补该条，不要硬读代码。

## 三、学习路线总览

六个阶段，按数据流顺序（先懂"数据从哪来"，再懂"模型怎么吃"，最后懂"怎么训练和评测"）。每阶段有明确验收标准，未通过不进下一阶段。按每天 2–3 小时估计，全程约 8–10 周；有基础者可压缩 Phase 0–1。

| 阶段 | 主题 | 时间 | 核心产出 |
|------|------|------|----------|
| Phase 0 | 论文通读 + 仓库全景 | 3–5 天 | 能白板画出端到端流水线与数据 shape 变换 |
| Phase 1 | 数据生成管线 | 1 周 | 理解 6 类任务的 QA 如何产生、对话 JSON 格式 |
| Phase 2 | LiDAR-CLIP 编码器 | 2 周 | 理解点云 → 768 维向量的全过程 + 特征文件体系 |
| Phase 3 | VTimeLLM 模型核心 | 2 周 | 手推 `<video>` token 替换与 labels 处理全流程 |
| Phase 4 | 训练工程（三阶段 + LoRA + ZeRO-3） | 2 周 | 说清每阶段"训什么、冻什么、为什么" |
| Phase 5 | 评测与论文对齐 | 1–2 周 | 看懂 B0 基线指标表，说出复现与论文的差距在哪 |

### Phase 2 — LiDAR-CLIP 编码器（2 周）

**目标**：理解"一帧点云如何变成一个 768 维向量，以及为什么要对齐 CLIP"。

**精读代码**（按序）：

2. `encoders/lidarclip/lidarclip/model/attention_pool.py` —— `AttentionPool2d`：BEV 特征图 → 单个 768 维向量（query 是可学习的 CLS，机制同 CLIP visual pooler）；`no_pooling=True` 时输出 BEV 图

### Phase 3 — VTimeLLM 模型核心（2 周）⭐ 全仓库最值得精读的部分

**目标**：彻底理解多模态特征如何注入 LLM。这是整个项目的"心脏"，也是面试/汇报时最常被追问的部分。

**知识前提补课**（B2 LoRA、B5 多模态 token 注入，在此阶段穿插完成）

**精读代码**（按序）：
1. `mllm/vtimellm/constants.py` + `conversation.py` —— `<video>` 特殊 token；`plain` / `vicuna_v1` 模板与 separator style
2. `mllm/vtimellm/model/vtimellm_arch.py` —— **核心中的核心**：
   - `initialize_vision_modules()`：`mm_projector = nn.Linear(768, hidden_size)`
   - `prepare_inputs_labels_for_multimodal()`：定位 `<video>` token → 投影特征 → 替换 embedding → labels 置 `IGNORE_INDEX` → padding/截断
3. `mllm/vtimellm/model/vtimellm_llama.py` —— 继承 `LlamaForCausalLM`，`forward()` 先融合再调父类
4. `mllm/vtimellm/model/builder.py` —— 推理时如何按 stage1/stage2/stage3 逐层加载权重（`merge_and_unload` 串联）
5. `mllm/vtimellm/train/dataset.py` —— `LazySupervisedDataset`：特征文件缺失时返回随机样本的静默容错（⚠️ 数据丢失要查日志）；时间戳两位数字编码；`feat_indices` 精确采样帧
6. `mllm/vtimellm/mm_utils.py` + `inference.py` —— 推理侧的 token 处理与生成

**配套文档**：`wiki/Architecture.md`、`docs/learn docs/VTimeLLM_analysis.md`

**动手任务**：
- **手推练习（最重要）**：拿一条真实训练样本（1 个 `<video>` token + 一轮对话），在纸上写出 `prepare_inputs_labels_for_multimodal()` 处理后的 `input_embeds` 形状与 `labels` 序列，标出哪段是视觉 token、哪段是问题、哪段是答案
- 用 `mllm/scripts/test_sample.py` 或 `eval_stage1_ppl.py` 在小数据上跑通一次前向

**自测（验收标准）**：

## 六、学习方法建议

1. **对照式读代码**：每个模块先读论文对应小节 → 再读 wiki 分页 → 最后读代码。论文公式与代码行对上时理解最牢。
2. **shape 标注习惯**：读任何模型代码时在草稿上持续标注张量 shape。本仓库的历史 bug 大半是维度/键名/格式不匹配，这个习惯直接迁移到调试能力。
3. **git log 学习法**：仓库有完整的中文提交历史，`git log --oneline` 按时间浏览，能还原"为什么这么改"的决策链（如 seqv3 --answer_frames 的由来）。
4. **先推理后训练**：跑通一条推理（`test_sample.py`）再理解训练，比直接啃训练脚本高效——推理代码路径短，能快速看到端到端效果。
5. **复现三原则**（来自本项目血泪教训，做实验时牢记）：
   - 训练与评测必须用**同代际格式**（metatoken / feat_indices 口径一致）
   - 新旧编码器特征**不可混提**（换权重必须全量重提）
   - 对比实验必须**单变量**且锁定基线（B0 规则）
