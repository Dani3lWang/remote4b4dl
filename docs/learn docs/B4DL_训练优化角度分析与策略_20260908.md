# B4DL 训练优化角度分析：除 RL 之外的可选策略（2026-09-08）

> 用途：在 SFT 管线与 RL 引进之外，从**输入构造 / 训练分布 / 数据利用 / 参数效率 /
> 训练效率**等角度盘点可行的训练优化策略。每条策略都锚定本仓库**已观测到的病灶**
> 与现成代码挂载点，并给出成本、预期、风险与实验纪律建议。
> 背景数字：B3 mIoU 0.3467（超论文 0.311）；B4a（TG 高帧段过采样）训练已完成，
> 评测截至 2026-09-08 12:40 尚未出 final metrics（29,805/30,145 进行中）。
> 环境实测：transformers 4.47.0 / peft 0.13.2 / torch 2.8.0——**DoRA 与 NEFTune
> 均原生可用**（本会话已验证），无需任何环境变更。

## 1. 先看病灶，再看药方

已观测事实（来自 B0-B4a 迭代文档与实测统计）：

| 病灶 | 证据 | 对应杠杆 |
|---|---|---|
| TG 输入**没有任何显式帧号信号**：问题文本无帧号（"When do the pedestrians appear?"）、meta 块只描述首末帧 ego 状态、特征就是 (40,768) 顺序堆叠 | B2 61% 预测坍缩到 (000,008)（先验拟合）；B1 学到"序列局部帧号"与评测全局编号错位 | **A. 帧身份锚点** |
| mIoU 是第一瓶颈指标，但 TG 只占训练 8.9%（13,124/148,271），且 start≥25 仅 14.9% | B4a 已对高帧段 ×2；TG 全局仍欠重 | **B. 任务分布重加权** |
| meta 语义曾是最大杠杆（meta2 +0.147 mIoU）→ 输入上下文工程还有空间 | B2→B3 实测 | **A 的一部分 / G** |
| 奖励函数（IoU/精确匹配）现成且零依赖，但只用在了评测 | §2 奖励语义目录 | **C. RFT / DPO** |
| 训练 3 epoch 固定、单卡 24-35h/run，迭代成本高；padding 到 2048 浪费大 | B4a 实测 24-36 s/step | **D. 训练效率** |
| LoRA r64/α128 固定；mm_projector 在 stage2 **被冻结** | stage2.sh / B 系列驱动器 | **E. 参数效率微调增强** |
| 训练数据 148k 条格式固定、无增广 | A5 注入产物 | **G. 数据增广** |

## 2. 策略 A：帧身份锚点（根因级，预期收益最大）

### 2.1 问题

模型如何知道"第 6 帧"在哪？现在只能靠**数位置**：40 个视觉 token 按序插在
`<video>` 处，帧号 = 序列内偏移。这个映射没有任何显式监督/锚点，B2 坍缩到
(0,8)、B1 局部编号错位，本质都是它。整场景输入（B2+）解决了坐标系问题，
但"数帧"仍完全靠位置记忆——B3 的 −3.9 帧系统性偏早也符合"位置估计漂移"特征。

### 2.2 三种实现（成本递增）

1. **文本锚点（最便宜）**：注入时给视觉序列加帧号文本，如 question 前加
   `"The sequence has 40 frames numbered 0 to 39."`，或把 meta 块扩成逐帧编号。
   改动 = `inject_metatoken.py`/`build_query` 一行模板 + 重训；**训练侧与评测侧
   同源注入**（既有约定天然满足）。风险：帧号 token 化不统一（"40" vs "040"）。
2. **可学习帧位置嵌入（推荐）**：`mm_projector` 输出 (N,4096) 后加
   `frame_embed = nn.Embedding(64, 4096)`，`z = z + frame_embed(arange(N))`。
   改动 = `vtimellm_arch.py` 约 6 行 + train.py 保存逻辑（帧嵌入随 non_lora 保存）；
   stage1 重训（投影器+帧嵌入一起，~3-4h）→ 主训练照旧。帧嵌入给模型一个**显式、
   单调、零文本**的帧身份先验，正对 TG 病灶；对复杂任务无害（可学习退化）。
3. **帧间轻量注意力**（如 1-2 层 temporal transformer / 1D conv 把 40 帧聚合成
   更少视觉 token）：表达力更强，但改动大、需要重训 stage1 且显存/速度变数多，
   建议在 1/2 验证有效后再考虑。

### 2.3 验收

同口径评测，看 TG mIoU 与"预测-全局帧号偏差分布"（−3.9 帧偏早应显著收窄）、
(0,8) 坍缩率是否归零。单变量实验（其余与 B3 完全一致）。

## 3. 策略 B：训练分布重加权（B4a 的自然推广）

B4a 已经证明了"数据侧分布干预"是仓库认可的手段。推广：

- **TG 全局过采样**：TG 13,124 → ×2~×3（不止高帧段），把 TG 训练占比从 8.9%
  提到 ~20%。mIoU 是北星指标，这是最直接的分布杠杆；
- **按任务平衡采样**：DataLoader 级采样权重，而非条目复制（`dataset.py` 加一个
  `task_weights` 即可，不影响磁盘数据与其它基线）；
- 与 B4a 的差异：B4a 只动 TG 高帧段（诊断性干预），本策略是 TG 全局（指标导向）；
- 风险：复杂任务 acc 可能微降（B0 基线已表明 TG 与文本指标存在张力），需要在
  最终表上全指标对齐。

---

## 4. 策略 C：RFT / DPO——奖励函数的"平价用法"（不需要 RL 循环）

§2 的奖励函数（TG IoU、简单任务精确匹配）现成且零依赖，除了做 RL 奖励，还可以：

- **RFT（Rejection Fine-Tuning）**：用 SFT 模型在**训练集**上采样（短答案任务
  ~0.5s/条，2-3 万条 4-6h），保留奖励最高的子集（如 TG IoU=1 的 42% 级子集 +
  简单任务命中子集），在原 LoRA 上继续 SFT 1-2 epoch。纯 SFT 代码路径（复用
  `run_*_mixed.sh`），无 RL 训练循环、无 KL、无比对学步，是 GRPO 之前**最稳的
  一步**；M1 的奖励审计脚本直接复用；
- **DPO**：对 TG 每条 prompt 用同模型采样 N 条 → 按 IoU 排序取 (chosen, rejected)
  对 → DPO loss（自写 ~50 行；peft/transformers 4.47 均支持）。比 RFT 用数据更
  充分（负样本也进梯度），比 GRPO 稳定（不需要 ref 模型/组优势），单卡友好；
- **⚠️ 污染红线**：数据必须来自**训练集场景**的采样。B4a 的 `predictions.json`
  （测试集 30,145 条）只能用于 M1 审计与事后分析，**绝不能**进 RFT/DPO 训练数据，
  否则评测集被污染、全部对照失效；
- 与 RL 的关系：RFT 是 GRPO 的廉价前置实验；若 RFT 已到收益天花板，再上 GRPO
  （三段式进程已设计）。

## 5. 策略 D：训练效率（单卡 24-35h 的每一点压缩）

| 手段 | 预期 | 注意 |
|---|---|---|
| **序列 packing**（多条 QA 拼一条序列，块对角 attention） | padding 浪费大（QA 文本 ~100-300 token vs max 2048），packing 可 ×2-3 吞吐 | 自定义多模态融合下实现有代价：视觉 token 插入位置需要按段偏移重算；**先做帧数分桶 + 动态 pad**（零风险版：collator 按桶 pad 而非 2048），packing 作为二期 |
| **动态 padding**：`DataCollatorForSupervisedDataset` 现在 pad 到 model_max_length 2048 | 短答案任务（~5 token 答案）当前浪费 90% 算力；桶内 pad 可 ×1.5-2 | 改动小：collator 按 batch 内最长 pad；attention 逻辑不受影响 |
| 混合精度复核 | mixed 系去掉了 tf32（seqv2 遗留），bf16+tf32 组合可再测 1-2% 提速 | 保持 bf16 权重，只动 matmul 精度，风险低 |
| 更长的 cosine 尾部 + 更多 epoch（5ep） | 24-35h→40-60h，收益不确定 | 与 packing 组合用：先提吞吐再提 epoch 数 |

## 6. 策略 E：参数效率微调增强（零成本超参/结构扫描）

- **DoRA**（peft 0.13 `LoraConfig(use_dora=True)` 已实测可用）：同 rank 下表达力
  更强，方向分解对 TG 这类"格式+数值"输出友好。改动 = 启动脚本加一行，重训对照；
- **r/α 扫描**：r64/α128 是继承配置，从未为 B4DL 扫过；r32 vs r128 对 148k 数据
  的过拟合/欠拟合边界值得一个消融；
- **解冻 mm_projector**（`--freeze_mm_mlp_adapter False`，或对 projector 也挂
  小 rank LoRA）：stage2 期间投影器被冻结，QA 任务的视觉适配全压在 LoRA 上；
  联合微调投影器（lr 1e-5 量级）可能提升视觉-文本对齐。风险小（投影器只有
  3.1M 参数）；
- **metatoken 两行 embedding 之外的文本侧**：`<meta>` 块里连接词/模板 token 也是
  冻结的，无必要动。

---

## 7. 策略 F：NEFTune 噪声嵌入

`TrainingArguments(neftune_noise_alpha=5)` 在 transformers 4.47 原生支持（本会话
已验证参数存在）：对输入 embedding 加少量噪声，已知能提升指令微调鲁棒性，对
TG 这类"位置估计"任务或有防坍缩效果。改动 = 一行参数；注意与 gradient
checkpointing/DeepSpeed 的组合需要一次冒烟（仓库有大量 monkey-patch 先例，
风险可控）。

---

## 8. 策略 G：数据增广（格式/帧号/meta 三路）

- **TG 格式变体**：GT 答案统一为 `from frame(s) X to frame(s) Y`，但模型可能从
  未见"`frames X–Y`"等评测解析器认可的其它形式（`extract_time_grounding_frames`
  支持 `to/-/and/until` 三式）。用 `re_render_meta.py` 同类的重渲染器把部分 GT
  改写成变体 → 模型格式泛化，评测解析失败率下降；
- **帧号抖动**：对描述类任务的引用帧号做 ±1 抖动 + 对应 meta 重渲染（复用
  `ego_text.render_meta_texts` 的任意 (first,last) 能力），增强帧号敏感性；
- **全帧 meta**：现 meta 只有首末帧。可在问题后追加逐帧简表（40 帧 × 极短描述，
  ~300 token）作为消融——成本是序列长度，与策略 A.1 文本锚点可合并实验；
- 前提约束不变：**训练/评测注入同源**（`ego_text.py` 三方共用），增广只改训练
  侧文本、评测侧 build_query 必须能重建同一格式。

---

## 9. 策略 H：高成本储备（暂缓，按需启动）

- **LiDAR-CLIP 编码器再训/再提**：编码器已定稿（val MSE 0.0992），重训编码器
  意味着全量重提特征 + stage1/2 重训，成本 1 周级。只有当 A-G 全部见顶、且
  分析指向"视觉特征质量是瓶颈"时才启动（可先用 val_mse_probe 对下游相关性做
  一次诊断）；
- **更大 base（Vicuna-13B）/ 更长上下文**：单卡 32GB + ZeRO-3 offload 勉强可行
  但 13B 训练吞吐会再降 2 倍，迭代速度不可接受，现阶段不推荐；
- **两阶段官方法 vs 混合法**：已实测对比（2026-08-26 决策），不再复开。

## 10. 实验纪律与验收口径（沿用既有约定）

1. **单变量**：每个消融只动一件事（B 系列的一贯纪律）；
2. **口径冻结**：评测永远 `--whole_scene --per_sequence --answer_frames`，
   ΔmIoU>0.013 才显著；任何输入构造改动必须训练/评测双侧同源；
3. **产物隔离**：新实验独占 output_dir / wandb project / eval_results 子目录；
4. **先审计再动手**：M1 奖励审计（B4a predictions 现成）会给出"当前策略在测试
   集上的失败模式分布"，A/B/C 的实验优先级应由它校准——例如若格式失败率 <1%，
   格式增广的优先级下调；若 (0,8) 坍缩残余显著，A 优先级上调。

---

## 11. 与 RL 的关系：正交，可组合，顺序建议

- **A（帧锚点）与 RL 完全正交**：帧嵌入/文本锚点是输入构造，RL 在同样构造上做
  策略优化，两者叠加；且 A 修的是 RL 也难学的"位置先验"，先 A 后 RL 会让 RL
  起点更好；
- **C（RFT/DPO）是 RL 的平价前置**：共享同一套奖励函数与采样管线（M1/M2 成果
  直接复用），先拿到"数据侧利用奖励"的收益与失败模式，再决定是否值得上 GRPO
  的三段式进程；
- **B（重加权）与 RL 存在部分重叠**（都是提高 TG 优先级），若走 RL 路线，
  B 可降级为"RL 数据采样权重"的一部分而非独立 SFT 实验。

**建议行动序列**：

```
现在         等 B4a 评测出结果（attempt #2 进行中）
第 1 步      M1 奖励审计（B4a predictions.json 现成，零 GPU）→ 校准优先级
第 2 步      小消融队列（按审计结论取 2 个）：
              候选 A.2 帧嵌入 / A.1 文本锚点 / E DoRA / B TG 重加权 / F NEFTune
第 3 步      C RFT（训练集采样 + 奖励过滤 + 续训 1-2 ep）——最接近"RL 收益"的平价实验
第 4 步      组合实验：A（定稿版）+ RFT 后的模型再接 GRPO（三段式，见可行性分析）
```

每一步都有现成代码挂载点与冻结口径的验收标准，不需要新基建。
