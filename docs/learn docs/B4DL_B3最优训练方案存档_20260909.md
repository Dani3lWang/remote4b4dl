# B4DL 最优训练方案存档：B3（整场景 + meta2）

> 存档时间：2026-09-09 ｜ 状态：当前最优基线（mIoU 0.3467 超论文 0.311，+0.036）
> 本文是**可复现配方**文档：数据 → 训练 → 评测 → 产物，全部命令与配置以仓库内实际脚本为准。
> 深层复盘见 `B4DL_B3整场景meta修复mIoU超论文_20260906.md`；演进全链见 wiki Reproduction-Log。

## 1. 一句话结论

**B3 = 整场景视觉输入（`--whole_scene`，与官方实现一致）+ 修复版 metatoken（meta2，对齐论文 §4.1 relative-to-previous）+ 官方 148,271 条混合单阶段训练（论文 §4.2 both）**，3 epochs / lr 1e-4 / LoRA r64·α128 / 162K stage1 projector，得全量评测 **mIoU 0.3467（论文 0.311）、acc 0.7526**，是当前 9 个基线版本里唯一全面超过论文 mIoU 的配置。

## 2. 为什么是这个组合（演进对照）

| 版本 | 视觉输入 | metatoken | 数据 | mIoU | acc | 结论 |
|---|---|---|---|---|---|---|
| 论文 Table 3 | 整场景 | 论文语义 | 148K 两段 | 0.311 | 0.762 | 目标 |
| B0 (seqv3-mixed) | per-seq 切片 | 旧渲染 | 148,271 | 0.2696 | 0.7629 | 锁定基线（08-27） |
| B1 | per-seq 切片 | 旧渲染 | 148,271 | 0.2653 | 0.7787 | 162K projector 重训 |
| B2 | **整场景** | 旧渲染（bug） | 148,271 | 0.1992 | 0.7649 | TG 61% 塌缩 000-008 |
| **B3** | **整场景** | **meta2（修复版）** | **148,271** | **0.3467** | 0.7526 | **超论文，最优** |
| B4a | 整场景 | meta2 | 150,222（TG 高帧段×2 过采样） | 0.3271 | 0.7775 | 负结果（Δ−0.0196），已排除过采样路线 |

- B2 → B3 的 +0.147 证明：mIoU 的第一瓶颈是 **meta 语义**（论文 §4.1 要求首末帧瞬时状态 relative-to-previous；旧渲染首帧恒 "at the starting position"+ 前向差分是错的），而非输入构造（整场景 vs 切片只差 ±0.06，见 B0/B1 vs B2/B3 交叉）。
- B4a 负结果反向证实：残余病灶是**输入无显式帧号信号**（见 wiki/Paper-vs-Reproduction #8），不是训练分布——高帧段过采样反而让预测向低帧集中（top-1 [06-14] 38.9%）。

## 3. 关键配置（权威来源：`mllm/scripts/run_stage2_full_seqv3_mixed_b3.sh`）

```
数据      mllm/b4dl_dataset/stage2_full_train_seqv3_meta2_148k.json   （148,271 条，官方 699 train scenes）
特征      encoders/lidarclip/b4dl/stage2_features/   （nuScenes 定稿编码器提取，scene 级 ~40 帧 float16）
projector mllm/checkpoints/vtimellm-vicuna-v1-5-7b-stage1/mm_projector.bin  （162K nu-caption 重训版）
输入      --whole_scene True      # 关键：视觉不再按 QA 序列切片，喂整场景，模型学全局帧编号
meta      meta2 渲染              # 关键：relative-to-previous 语义（re_render_meta.py 重注入 113,053 条）
--lora_enable True  --lora_r 64  --lora_alpha 128   --weight_decay 0.
--num_train_epochs 3  --per_device_train_batch_size 8  --gradient_accumulation_steps 16
          → 每 step 128 条，共 3,474 步（= 148,271×3/128，trainer_state 实测 epoch 2.999）
--learning_rate 1e-4  --warmup_ratio 0.03  --lr_scheduler_type cosine
--bf16 True  --gradient_checkpointing True  --model_max_length 2048
--freeze_mm_mlp_adapter True   # projector 冻结，只训 LoRA + metatoken embedding（train_meta_embed 默认开）
--save_strategy steps --save_steps 200 --save_total_limit 3
--deepspeed ./scripts/zero3.json（ZeRO-3 单卡）  --report_to wandb（WANDB_MODE=offline）
环境      wqlc conda env（torch 2.8.0+cu128 / transformers 4.47.0 / peft 0.13.2，wqlc 在
          /root/autodl-tmp/.conda-stuff/envs/wqlc；训练用 /root/autodl-tmp/miniconda3 的 conda）
```

注意：`run_stage2_full_seqv3_mixed_b3.sh` 文件头注释沿袭 B2 文案（写 "B2 混合训练…唯一差异 --whole_scene"），实际以脚本体内 OUT=…-mixed-b3、WANDB_PROJECT=…-b3、meta2 数据路径为准。

## 4. 数据与特征前置（复用现成产物，重跑无需再做）

1. **编码器**：nuScenes 自训定稿 `encoders/lidarclip/ckpt_anneal/lidarclip_mm/last.ckpt`（退火后 val MSE 0.0992，比 ONCE 基线 −6.5%）。
2. **特征**：定稿编码器 eval 模式全量重提——stage1 `stage1_features_sample/`（28,130 帧 sample_token 键控）+ stage2 `stage2_features/`（850 scenes）。
3. **stage1 projector**：162K 官方对齐版（`stage1_train.json` 161,629 条 / 699 scenes，2026-08-28）。
4. **meta2 数据**：修复版 meta 渲染（ego_text.py 的 spd_prev/yaw_prev/acc_prev + 相对前一帧位移；`re_render_meta.py` 对 113,053 条重注入；帧运动表 `ego_frame_motion.json` 34,149 帧）。
5. **TG 序列归属**：seqv3 管线产物（`--answer_frames` 双侧解析，13,124 条 TG 零 per-scene 回退）已固化在 meta2 json 内，重训练直接消费。

## 5. 执行（含门控外壳，来源：`mllm/scripts/run_b3_pipeline.sh`）

```bash
# 单条训练（脚本内含断点续训：sort -V 取最新 checkpoint-*，mllm train.py 同规则）
bash mllm/scripts/run_stage2_full_seqv3_mixed_b3.sh
# 完整两阶段链（阶段1 训练 → 阶段2 评测；28GB 显存门控 72h/14GB 门控 5 次，各含重试与判据化验收）
bash mllm/scripts/run_b3_pipeline.sh 1     # tmux 分离会话运行；[1|2] 指定从哪阶段起
```

- 训练判据：`adapter_model.safetensors` + `trainer_state.json` 中 epoch ≥ 2.99 才视为完成；中断自动 `--resume_from_checkpoint`。
- 评测阶段 2 命令（全量 30,145 条，0 skip，约 2.5-3h，`timeout 18000`）：
  `evaluation/test_b4dl.py --model_base ./base_model/vicuna-v1-5-7b --pretrain_mm_mlp_adapter <stage1>/mm_projector.bin --stage2 <mixed-b3 顶层> --feat_folder ../encoders/lidarclip/b4dl/stage2_features --test_data ./b4dl_dataset/test_qa.json --ego_meta ./b4dl_dataset/ego_metadata.json --frame_motion ./b4dl_dataset/ego_frame_motion.json --whole_scene --per_sequence --answer_frames --output …/predictions.json --metrics_output …/metrics.json`
  （评测用 wqlc 的 python 绝对路径 + `HF_HUB_OFFLINE=1 HF_OFFLINE=1 TRANSFORMERS_OFFLINE=1`，重定向必须 `-u`）

## 8. 复现注意事项（踩坑汇总）

1. 训练进程必须 **tmux 分离会话**（ZCode/harness 后台任务与 nohup 会被顺进程树回收；守护 cron 见 automation 记录）。
2. 共享 GPU：训练前等 28GB 门控、评测等 14GB；`nvidia-smi` 只读检查他人进程，勿动（CoRViD/xmuda/lhwt 等）。
3. pkill 自匹配坑：模式串勿含自身，用 `[t]rain_mem` bracket trick。
4. 加载官方/旧 checkpoint 注意 peft 版本字段兼容（本地 0.13.2，官方 0.19.1 的 alora 字段需最小化 adapter_config）。
5. 对比口径：B 系间对比必须同 METEOR 后端；mIoU 闭区间 + 完全不相交区间归零；ΔmIoU > +0.013 才算真改进（B0 基线重置条件：换编码器/重提特征/改口径/换测试集——B1 起已全部满足，B3 相对 B1/B2 同口径可比）。
6. 推理用 greedy（do_sample=False）保证可复现。
