## 二、数据侧量化审计（对齐缺口的规模）

训练集 `stage2_full_train_seq.json`（118,722 条）按问题帧号与序列边界匹配情况：

| 类别 | 条数 | 占比 | 旧代码行为 | 论文应为 |
|------|------|------|-----------|---------|
| 引用=序列边界 | 54,062 | 45.5% | per-seq ego ✅ + 切片=序列 ✅ | 不变 |
| 引用≠边界（子区间/单帧） | 25,913 | 21.8% | **per-scene ego ❌ + 切片=子区间 ❌** | QA 引用帧的真实 ego + 整段包含序列 |
| 问题无帧号 | 38,747 | 32.6% | per-scene ego + 全 scene 特征 | 同左（序列归属不可恢复，见 R5） |

测试集 `test_qa.json`（30,145 条）：time_grounding 2,783 条 100% 无帧号；
description 3,770 条中 2,561 条引用≠边界（68% 受 B1/B2 影响）。

R5（数据级限制，无法在代码侧解决）：发布的 QA JSON 不记录每条 QA 所属序列，
time_grounding 类问题（无帧号）在推理时只能用全 scene 特征 + per-scene ego。
训练侧保持一致（同样不切），属于自洽的近似。

## 三、本次修复明细

### 1. `evaluation/evaluate_model.py` — mIoU 闭区间修正
- `inter = min(pe,ge) - max(ps,gs) + 1`（闭区间长度），union 同步 +1。
- `extract_time_grounding_frames` 无匹配返回 `None` → 该样本 IoU 记 0（原为
  `{0,0}`，与 GT `[0,x]` 产生虚假重叠）。
- 单测：单帧完美匹配 1.0、精确匹配 1.0、部分重叠 5/15、无解析 0.0 ✅

### 2. `scripts/ego_text.py`（新）— metatoken 渲染单一来源
- 全部 ego 文本模板（位置/地形/转向/速度/加速度）集中于此，供
  `generate_ego_metadata.py`、`inject_metatoken.py`、`test_b4dl.py` 三方共用，
  保证训练注入与推理注入逐字符一致。
- `render_meta_texts(frames, first, last)`：对**任意** (first, last) 帧对渲染
  首末帧描述；单帧引用时输出真实邻帧运动（修复 B5 伪造 stationary）。

### 3. `scripts/generate_ego_metadata.py` — 逐帧运动表
- 模板改为从 `ego_text.py` 导入（删除本地副本）。
- 新增 `--frame_motion`：输出 `ego_frame_motion.json`，每 scene 全帧记录
  `{x,y,z,yaw,spd_next,spd_prev,yaw_next,yaw_prev,acc_next,acc_prev}`。
- 原有 per-scene / per-sequence 文本条目输出不变（向后兼容）。

### 4. `scripts/inject_metatoken.py` — v2 注入
- `--frame_motion`：对任意 QA 引用帧对渲染**真实** metatoken（消除 B1 的
  per-scene 回退错误）。
- `--sequence_metadata`：为每条有帧号的 QA 计算包含序列（多个重叠序列取
  最窄包含；无包含取最大重叠），写入：
  - `item["feat_indices"] = [i0, i1, ...]`：序列的**精确采样帧**（如
    `[0,2,4,6,8]`，论文 §3.3 采样帧集合，训练/评测选帧首选）
  - `item["feat_range"] = [s, e]`：序列首末帧闭区间（兼容与 frame_ctx 前缀用）
- `--frame_ctx` 前缀改用 `feat_range` 边界（此前用 QA 引用号，与切片不一致）。
- legacy 模式（不传新参数）行为与旧版完全一致。
- 生成统计：118,722 条中 79,975 条有帧号 QA **全部**获得真实帧 metatoken
  （v2_rendered，零 per-scene 回退）+ feat_indices 全命中；38,747 条无帧号
  QA 保持 per-scene ego + 全 scene 特征（自洽）。

### 5. `vtimellm/train/dataset.py`
- 特征切片优先读 `item["feat_range"]`（包含序列），无字段回退问题帧号解析
  （兼容旧数据文件）。删除 VTimeLLM `meta` 帧号百分化死代码（B6）。

### 6. `evaluation/test_b4dl.py`
- `--frame_ctx` 独立开关（默认 OFF）：`--per_sequence` 回归纯论文语义
  （切片 + per-seq/per-frame ego），frame-context 前缀只在评测 seqctx 变体
  模型时显式加（B4）。
- `--frame_motion`：推理时用与训练注入**同一渲染器**生成 metatoken。
- `--sequence_metadata`：特征切片到包含序列（与训练 feat_range 同逻辑）。
- 优先读 item 自带 `feat_range` 字段。

### 7. `vtimellm/inference.py`
- `do_sample` 参数（默认 False=greedy），评测确定可复现（R3）。

## 四、对齐后的数据/命令链

```bash
# 1. 生成 ego 数据（文本条目 + 逐帧运动表）
python scripts/generate_ego_metadata.py \
    --nuscenes_root /root/autodl-tmp/Datasets/nuScenes \
    --scene_metadata ../encoders/lidarclip/annotations/scene_metadata.json \
    --sequence_metadata ../encoders/lidarclip/annotations/sequence_metadata.json \
    --output ./b4dl_dataset/ego_metadata.json \
    --frame_motion ./b4dl_dataset/ego_frame_motion.json

# 2. v2 论文对齐训练数据（真实 metatoken + feat_range）
python scripts/inject_metatoken.py \
    --input ./b4dl_dataset/stage2_full_train.json \
    --ego_meta ./b4dl_dataset/ego_metadata.json \
    --frame_motion ./b4dl_dataset/ego_frame_motion.json \
    --sequence_metadata ../encoders/lidarclip/annotations/sequence_metadata.json \
    --output ./b4dl_dataset/stage2_full_train_seqv2.json

# 3. 训练（复用 run_stage2_full_seq.sh，data_path 换 seqv2 文件）

# 4. 论文对齐评测
python evaluation/test_b4dl.py ... --per_sequence \
    --ego_meta ./b4dl_dataset/ego_metadata.json \
    --frame_motion ./b4dl_dataset/ego_frame_motion.json \
    --sequence_metadata ../encoders/lidarclip/annotations/sequence_metadata.json

# seqctx 变体模型评测：在上面基础上再加 --frame_ctx
```

## 五、遗留与说明

- **R2**：`<4DLiDAR>/<meta>` 嵌入行训练是论文未描述的工程补充（论文未说明
  新 token 如何进 Vicuna 词表）。保持默认开启，重训时保持一致即可。
- **R5**：time_grounding 推理只能全 scene 输入（benchmark 数据未带序列归属）。
- 旧 checkpoint（stage2-full / stage2-full-seq）与新评测格式的配对规则不变：
  **训练与评测格式必须同代**。seqv2 数据训练出的模型才能配 v2 评测。
- seqctx（frame-context）是自创干预，论文没有；它作为 mode-collapse 的
  实验分支保留，不进入论文对齐主线。
