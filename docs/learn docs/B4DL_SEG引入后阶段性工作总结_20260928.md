# B4DL 引入 SEG 后的阶段性工作总结

统计区间：2026-09-17 首次实现至 2026-09-28。Git 截止本地 `seg` 分支 `d4a0913`；完整实验数值依据当天三机审计快照，A1 状态另于北京时间 18:54 补查。

## 一、阶段定位与总体成果

这一阶段完成了从“B4DL 输出文本问答”到“语言指令驱动点级实例掩码”的功能扩展，并建立了围绕数据、训练、推理、评测和故障定位的实验工具。工作已从移植与数值稳定性排障，推进到空间表示、实例区分和时序信息的研究。

当前可以确认：

1. **功能链路已经实现并实际训练、推理过。** 单帧点云可经过空间编码器、场景 token、语言模型、`<LOC>/<SEG>` 路由和掩码头生成点级分割结果。
2. **编码器预训练是已得到完整模型证据支持的有效改进。** 同一300条自由生成存档复算中，旧编码器命中1/330，新编码器命中22/330，扩场景配方命中28/330。
3. **已经进行了系统的瓶颈诊断。** 覆盖损失重加权、Tversky、LOC先验、阈值、Oracle query、编码器冻结/解冻、语义保持、多任务监督、训练预算和多帧输入。
4. **可靠性建设是本阶段的重要产出。** 修复了特殊token参数NaN、推理解码错误、验证OOM、TF分母漂移、in-range索引错误和多帧坐标错误；增加恢复契约、负例准备、分类头保存与测试。
5. **尚未完成最终效果验收。** 当前自由生成结果仍是300条子集；多任务和时序主要在Oracle路径验证，缺少新编码器接回完整模型后的最终生成评估、独立保留集、多seed及SEG适配后的B3回归。

准确的阶段定位是：**完成研究原型与主要工程排障，获得有效的编码器改进证据，正在验证实例接地与多帧方案；尚未形成可宣称最终性能达标的模型。**

### 问题及对应办法

| 问题 | 采用的办法 | 状态与边界 |
|---|---|---|
| 新增token可能破坏B3 checkpoint的32002行embedding恢复 | loader先恢复Vicuna、Stage1与B3，再注册SEG token，使用独立token adapter与SEG LoRA | 加载顺序已实现；不代表加载SEG后B3能力已通过回归 |

这一阶段解决了“功能如何接上”，还没有解决“实例能否分得准”。

## 四、阶段二：训练跑通、数值稳定性和空间预训练（09-18—21）

核心提交：`674bc59`、`2d4b8ec`、`95ea3cc`；相关实验包括mini smoke、mini4090、trainval4090、学习率/recipe-B短跑、空间FP32预训练及tvenc。

| 问题与现象 | 已做工作/解决办法 | 实验证据与当前判断 |
|---|---|---|
| 首次SEG训练第1步loss约11.4206，随后NaN | 特殊token输入delta与输出行用FP32主参数存储，前向再转换计算dtype；避免小梯度下低精度优化状态不稳定 | `674bc59`；下一次smoke完成16步，说明该次早期数值故障得到缓解 |
| mini数据版本与场景划分不匹配 | 数据生成器支持mini_train/mini_val | `674bc59`；mini实验可以开展 |
| smoke保存时ENOSPC | 增加`--no-resume-state`与`--keep-last`，支持精简保存及轮转 | `2d4b8ec`；避免每次写完整accelerator状态；代价是精简档不能精确续训 |
| 磁盘存在大权重文件，容易误判训练成功 | 结合退出码、日志、完整checkpoint元数据判定 | 42105第二次smoke exit=1；残留约7.8GB文件不能当成功保存证明 |
| 小规模空间预训练能力弱 | 扩大空间语义预训练规模；低精度失败后改FP32 | 旧mini记录mIoU0.1244；FP32大规模跑满12轮，历史best mIoU0.28758。两者协议不同，不直接作为公平提升比例 |
| mini训练效果低，文本损失小但mask仍弱 | 扩展至trainval、尝试学习率和dropout配方、更换空间权重 | mini best TF0.00747，仅32目标；trainval best TF0.01652；tvenc best TF0.10366 |
| 探索配方容易被误认为已充分排除 | 核查实际轮数和共同变更项 | lr5e4仅3轮；recipe-B同时改lr和dropout，日志未跑满12轮；不能宣布学习率/dropout整条路线无效 |

mini4090现存日志到ep15、8224 steps，不能写成20轮全部完成。末步总loss约1.336、mask_seg约0.860，准确描述是文本/类别分支快速拟合、掩码分支仍弱，不能说所有训练loss都归零。

本阶段最重要的结果，是为后续完整模型提供了更有效的空间编码器。其作用随后由同样本自由生成复算进一步确认。

### 完整模型实际效果

同一300条、330个GT目标、encoder FP32、阈值0.5、本次CPU复算：

| 完整模型配方 | 命中 | Recall@0.5 | cIoU面积加权 | gIoU逐对平均 |
|---|---:|---:|---:|---:|
| 旧空间编码器trainval4090 | 1/330 | 0.303% | 0.05060 | 0.00790 |
| 新空间编码器tvenc | 22/330 | 6.667% | 0.22876 | 0.08812 |
| 扩场景tvenc680 | 28/330 | 8.485% | 0.22597 | 0.10085 |
| internal679 | 24/330 | 7.273% | 0.23690 | 0.09069 |

更换编码器得到明确收益。扩场景增加6个命中是积极信号，但缺少多seed和独立测试，不能断言统计显著。internal679更重要的价值还包括后续实例训练的内部选轮协议，不宜仅按上表认定“回退”。这些命中按类别无关IoU匹配计算，类别正确性需要另行报告。

## 六、阶段四：空掩码、损失与LOC先验消融（09-23—25）

相关提交：`3bd8991`、`053fcb6`、`04ec539`、`78cf410`、`590a0f4`、`617a90d`。

### 已做工作

- 实现接地诊断：逐点AUC、GT数量top-K、正负点概率、LOC覆盖和预测点数分布。
- 实现阈值扫描、离线失败分解、类别与序数分桶。
- 给掩码损失增加plain/balanced BCE与Dice/Tversky组合；损失字段与结构字段分开，避免新损失档无法加载。
- 实施三臂4轮筛选，候选Tversky自动扩到20轮。
- 先做推理时LOC先验置零，再实现训练期关闭先验的B1，避免只靠推理突变判断先验价值。

| 遇到的问题 | 采用的办法 | 实际结果与判断 |
|---|---|---|
| 正点极少，模型倾向不触发 | balanced BCE提高正侧权重 | 两条balanced配方预测中位约1500–1713点，GT约11点，出现严重过分割；这两份配方不宜直接沿用 |
| 普通Dice配方召回弱 | plain BCE＋Tversky，增加漏检相对代价 | 4轮best内部TF0.12546，扩20轮best0.14437；但不同验证口径不可混比 |
| 掩码尺寸改善是否真正解决实例选择 | 同样本自由生成和目标配对复查 | 空掩码目标标签140→99；命中仍24；19共同、5新增、5丢失；平均IoU升、面积加权IoU降，属于部分改善 |
| LOC先验可能过度抑制 | 推理置零、相对阈值、训练期no-prior B1 | 置零后AUC升但尺寸膨胀、命中下降；B1新口径AUC较高，命中没有同步改善 |
| TF单指标可能误选模型 | 同报mean/global IoU与hits | reachable上internal679为207/2278，Tversky为186/2278，B1为188/2278；B1仅4轮，不据此裁定公平预算下优劣 |
| 生成文本正确却分错同类目标 | 按序数、类别、位置失败分解 | 4及以上序数桶在两组存档中均0命中；需要增强几何关系和实例身份区分 |

本阶段的重要认识是：**掩码触发数量、逐点排序、实例身份和IoU命中不是同一件事。** 修好空掩码，不能自动解决“到底分的是哪辆车”。

## 七、阶段五：Oracle定位、编码器微调与语义多任务（09-25—27）

### 从“语言是否没表达清楚”推进到“给定GT条件能否分割”

`5a34323`加入Oracle query，用GT中心与类别替代语言路径；`057cf1e`增加逐轮选优和top-K；`0ad6205`增加解冻；`c4b7d77`调整encoder学习率并固定BN统计；`9bce615`增加体素并列诊断。

| 问题 | 已采用的办法 | 结果及边界 |
|---|---|---|
| 无法区分语言query与空间解码的瓶颈 | GT中心＋类别构造Oracle query | 可以剥离语言条件误差；仍受query MLP、解码器和优化限制，不是理论上限 |
| v1只看末轮、结果不稳定 | v2按dev逐轮选优、补top-K | v1是600条/623目标，v2以后400条/416目标；不能直接横排v1 |
| 冻结特征是否限制适配 | v3解冻编码器 | 命中从9.62%到14.42%；参数确有更新，不能称“完全没有微调” |
| 小学习率、BN统计与预算混在一起 | v4提高encoder学习率至5e-5、固定BN eval、跑20轮 | 命中24.76%；有效，但多因素同时变化，不能只归因于BN或学习率 |
| 体素内同分是否导致排序上限 | 测量同体素正负点并列 | 可检查并列机制，但不能据此排除分辨率或感受野改动 |

## 十一、对历史结论的修订

本阶段应保留失败实验与排障成果，同时收紧超出证据的结论。

- **“单帧点特征不可能接地”**应改为“当前结构、预算与数据协议下，单帧实例接地仍弱”。Oracle也包含有限的查询网络和解码器。
- **“AUC≥1−K/N才可能top-K命中”**不是必要条件。例：12个正点中8个排在全部负点之前，4个在其后；AUC约0.667，top-12仍可得到IoU=8/16=0.5。因此“距门槛16.9倍”不能作为物理上限或可行性定案。
- **“损失没改变结果”**应改为“总命中无净增益，但目标交换、掩码尺寸和两种IoU有变化”。
- **“语义与实例共存已证明无代价泛化”**应改为“当前线性probe协议下语义保持改善，独立跨任务场景验证待补”。
- **“30轮平台证明继续优化无用”**应改为“本次扩预算边际收益有限；只有单次轨迹，不能排除其他架构或优化方式”。
- **“A2偏离即度量损坏”**应改为“先做同权重eval模式复制不变性检查，再用重复训练区分数值与优化轨迹差异”。
- **“提交了修复就修好了旧实验”**应改为“代码修复、运行采用、产物验证分别登记”。已运行进程和历史checkpoint不会自动得到后来的修复。
