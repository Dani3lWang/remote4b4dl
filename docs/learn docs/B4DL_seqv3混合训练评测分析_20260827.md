## 二、训练方案

### 2.1 数据（seqv3，对齐论文官方 148K 划分）

- 训练集：`b4dl_dataset/stage2_full_train_seqv3_148k.json`，**148,271 条**（stage2 简单任务 + stage3 复杂任务全量混合，论文官方训练集，699 scenes）
- 相对 seqv2 的新增量（commit `8b85cd2`/`d228409`）：
  - TG 13,124 条**全部恢复 GT 序列归属**（benchmark 发布时丢了序列归属字段，从 GT 答案帧范围 100% 恢复：2645 唯一 + 138 歧义）
  - 真实帧 metatoken（`ego_frame_motion.json` 逐帧运动表，v2 渲染，零 per-scene 回退）
  - `feat_indices` 精确采样帧（按包含序列采样，不混入非序列帧）
- 测试集：`test_qa.json`，30,145 条 × 6 任务（150 scenes，与训练集零重叠）

### 2.2 模型

- base：vicuna-v1-5-7b（`base_model/vicuna-v1-5-7b`）
- 投影层：**95K nu-caption 重训版 stage1 projector**（08-25 17:46 训完，742 步；替代旧 699 条欠训练版）
- 适配器：单 LoRA（r64 / α128），`--freeze_mm_mlp_adapter`，train_meta_embed 开

### 2.3 超参数（对齐 seqv2-148k 的 acc 0.7647 配置）

| learning rate | 1e-4，cosine，warmup 0.03 |
| batch size | 8 × 16 grad accum = 128 |
| 精度 | bf16，DeepSpeed ZeRO-3，gradient checkpointing |

| 其他 | `PYTORCH_CUDA_ALLOC_CONF=expandable_segments`，wandb offline |

### 2.4 执行

- 脚本：`scripts/run_stage2_full_seqv3_mixed.sh`（tmux b4dlmixed，自带断点续训）
- 时间：2026-08-26 13:19 → 08-27 12:14，约 23 小时（与 CoRViD 训练共存，单卡 5090 32GB）
- Loss：8.70（step 1）→ 1.37（step 200）→ 稳定在 **1.05–1.17**（收敛正常，grad_norm ~0.6）
- 产物：`checkpoints/vtimellm-vicuna-v1-5-7b-stage2-full-seqv3-mixed/`（最终 adapter 320MB）

## 三、评测方案

- 脚本：`evaluation/test_b4dl.py`（论文对齐：6 任务 × 7 指标，Metatoken 前缀 `<4DLiDAR> + <video> + question + <meta>` 推理期注入）
- 参数：`--per_sequence --frame_motion --sequence_metadata --answer_frames`（与两阶段评测完全同口径）
- 关键口径：`--answer_frames` = TG 从 GT 答案帧范围恢复序列归属（**oracle 输入选择**，GT 仅用于选输入帧/metatoken，不进入模型提示）；`--sequence_metadata` 做包含序列特征切片
- 执行：08-27 17:02 → 19:28（约 2.5h），30,145 条全量，**0 条跳过**
- 说明：评测期间 GPU 与 CoRViD 训练争用，脚本加了显存门控与 HF offline 保护（见 §五.4 环境注记）

## 五、结果分析

### 5.1 QA 精度坍缩已修复（混合训练验证成功）

- accuracy 0.7629 与论文 0.762 持平，两阶段的 0.0001 彻底消失（existence 0.707、binary_qa 0.819 均健康）
- 验证了决策判断：混合训练（论文 §4.2 原文做法）是正确路径，两阶段法的格式漂移是其固有缺陷（Phase B 长句格式覆盖 Phase A 短答案）
- 该结果与 seqv2-148k（0.7647）同一水平，说明 seqv3 数据增量对 QA 精度无损

### 5.2 mIoU 大幅提升（+47%），TG 序列归属 + 95K projector 净收益明确

- mIoU 0.2696 是历史最高（seqv2 0.1835 / 两阶段 0.1614 / baseline 0.1661）
- 改善来自两个叠加因素：① seqv3 的 GT 序列归属 + 真实帧 metatoken + 精确采样帧（训练侧与评测侧一致）；② 95K nu-caption 重训的 projector（更强的场景级映射）
- 预测多样性改善：33 种 vs 15/6 种，精确命中率翻倍（13.9% vs 6.3%），无帧号预测几乎消失

### 5.3 剩余差距：mIoU 0.270 vs 论文 0.311（差 0.041），根因聚焦"帧级定位未学会"

本次 TG 分布分析给出了比之前更清晰的证据链：

1. **模型学会了"宽度"，没学会"位置"**：预测宽度与 GT 一致（11.1 vs 10.4 帧），但中心偏移中位数达 10 帧、99.6% 的预测挤在 scene 前 10 帧。模型本质上是在输出训练集里出现频率最高的滑窗位置（(0,8)、(6,14)、(4,20)…），这是**先验拟合而非时序定位**。
2. 按嫌疑排序（沿用 08-26 报告 §4.2，本结果进一步强化）：
   - **① stage1 projector 数据量（最大嫌疑）**：95,048 条 ≈ 论文 162K 的 59%。projector 是单层 Linear(768→4096)，把 LiDAR 帧特征映射到 LLM 空间；数据不足 → 学到的是"场景级"映射而非"帧级"映射，模型无法区分帧号 → 无法定位。这与"宽度对、位置错"的表现完全吻合（区分帧相对顺序比区分宽度更需要帧级表示）。
   - ② TG 评测口径：整数区间 vs 采样帧集合 IoU 差异仅 ±0.02（已实测排除）
   - ③ LiDAR-CLIP 编码器权重版本待核对（影响全部任务，但对 TG 的帧级判别影响最大）
   - ④ 推理解码策略：当前 greedy，论文大概率一致（低嫌疑）
3. 结论：**下一步行动 = 把 stage1 数据补到 ~162K（为剩余关键帧跑 LiDAR-CLIP 特征提取）→ 重训 projector → 混合重训**，这是 mIoU 冲击 0.311 的最优路径。

### 5.4 环境注记（本机评测的坑，已修复并固化进脚本）

- **HF Hub 网络卡死**：本机访问 huggingface.co 的 TCP 半开（curl 超时），transformers/peft 加载模型时的 hub 版本检查会让进程**永久挂起** → 必须设 `HF_HUB_OFFLINE=1 HF_OFFLINE=1 TRANSFORMERS_OFFLINE=1`
- **GPU 争用**：与 lhwt 的 CoRViD 训练（19GB）共存，评测需 ~12.5GB 必 OOM → 显存门控循环（空闲 <14GB 每 10 分钟重试）
- 输出重定向必须 `-u`（否则看不到进度），并加 timeout 防挂死
- 经验固化：`scripts/run_mixed_eval_after_train.sh`

## 六、结论

1. **seqv3 混合训练方案成立**：acc 0.7629 ≈ 论文 0.762（坍缩修复），文本类指标全线 ≥ 论文，mIoU 0.2696 创历史新高。该方案 = 论文官方 148K 划分 + seqv3 序列归属数据 + 95K projector + 混合训练超参（3ep / lr 1e-4）。
2. **核心短板收敛到一个点**：TG 帧级定位。模型已能生成结构正确的帧区间（宽度、格式），但位置依赖先验（99.6% 预测起始帧 <10 帧）。证据链指向 stage1 projector 欠训练。
3. 建议按序执行：**stage1 补数据至 ~162K → projector 重训 → seqv3-mixed 重训 → 评测**，目标 mIoU ≥ 0.30。
