# B4DL ReasonSeg 实验总结（2026-09-18 ~ 09-27，autodl3）

**性质**：阶段性总结报告。数据全部来自 autodl3 上直接读盘（`training_logs/`、`eval_results/*/metrics.json`、`report.json`、git 历史），不引用对话记忆。带日期的逐时刻快照在 `B4DL_ReasonSeg训练现状_20260925.md`，本文件只留**结论、机制与可引用数字**。

---

## 0. 一句话

ReasonSeg（单帧点级推理分割）在 B4DL/nuScenes 上的 val mIoU 长期贴近 0，本轮把六条候选杠杆逐一判死、把瓶颈定位到机制级，最后用 oracle-query 探针量出了**瓶颈的物理位置**：**一个 12 点的物体要在约 32,530 个框内点里被单独分出来，单帧点特征做不到** —— 即使把完美定位与类别直接喂给解码器、即使把编码器真的大幅度改造过，排序质量也停在 AUC 0.995–0.9976 的平台上，距 top-K 所需的 0.99963 差 8–26 倍。

同时得到一个**正面的、可用的结论**：语义（lidarseg）与实例两个训练目标**可以共存于同一份特征** —— 加语义锚之后编码器被改造 21.8%，线性探针语义 mIoU 不降反升到 **0.33109**（预训练基线 0.30785，纯实例微调则塌到 0.22073）。

## 4. 七条杠杆全部判死（每条带机制）

| # | 杠杆 | 判死证据 |
|---|---|---|
| 1 | lr / head dropout | 5e-4 与 dropout 0 两个对照实验均无改善 |
| 2 | 场景数（数据规模） | 200→680 场景等算力对照：0.1037→0.1128，落在"不显著"档 |
| 3 | 语言侧 / query 通路 | 条件化探针：掩码头退化为类先验 + 全局面积；answer 侧主导语言 |
| 4 | 二值化阈值 | 0.3/0.5 扫描 + 相对阈值解码族：命中率不动 |
| 5 | 数据协议 | 无泄漏 internal 协议重跑后，对照与旧的相对关系不变 |
| 6 | 空间编码器 | 换代拿到 6.3×（0.0165→0.1037）——**这是唯一真正有效的杠杆**，但自由生成 recall 仍只有 5.3% |
| 7 | 损失函数 | A2-ext20 20ep 扩跑：尺寸塌缩治好（1.00× GT）、空掩码 −41，但 hit 24/330 **逐位不动**、recall@0.5 与 global IoU 反而更差 |

**关键读法**：A2 之后失败分解把 `right_class_wrong_place` 抬成第一大失败模式（87→102）—— 模型知道类别、知道大致在哪一片，**就是不知道是哪一个实例**。这是实例接地失败，不是分割失败，任何损失重加权都治不了。

## 5. 瓶颈定位：oracle-query 探针四跑

探针绕过 7B LM，用 **GT 中心（按 `point_cloud_range` 归一化）+ one-hot 类别**构造 query，只训 `OracleQueryNet` + `QueryMaskDecoder`，其余与真实头同构（逐物体 memory 展开）。它量的是**天花板**。

| | test AUC | recall@0.5 | recall_top_k | iou_mean | 尺寸 | 卷积权重变化 | 收敛性 |
|---|---|---|---|---|---|---|---|
| v2 冻结编码器 6ep | 0.99110 | 0.09615 | 0.11058 | 0.15856 | 29/12 | 0% | 未收敛（选 ep4，ep5 AUC 更高） |
| v3 解冻 lr1e-5 6ep | **0.99510** | 0.14423 | 0.18990 | 0.19197 | 17/12 | **3.52%（假微调）** | 未收敛（选末轮） |
| v4 解冻 lr5e-5 20ep + BN 钉 | 0.99038 | 0.24760 | **0.33890** | 0.28710 | 23/12 | 19.97% | dev AUC ep5 见顶后回落 |
| **多任务 语义+实例 20ep** | **0.99575** | **0.26440** | 0.31970 | **0.29910** | 22/12 | 21.81% | **dev AUC 11 轮平台** |

**先验门槛**（与任何观测无关，故不是事后拟合）：top-K 解码要命中需 AUC ≥ 1 − K/N，K = GT 尺寸中位 12、N ≈ 32,530 框内点 ⇒ **0.99963**。换算成"压在正点之上的负点数"（= (1−AUC)×N，需 ≤12）：

| | AUC | 负点数 | 差距 |
|---|---|---|---|
| 完整模型（对照，无偏诊断） | 0.8755 | ~4,050 | 338× |
| oracle v2（冻结） | 0.99110 | ~289 | 24× |
| oracle v4（真微调、纯实例） | 0.99038 | ~313 | 26× |
| oracle 多任务 | 0.99575 | ~138 | 11.5× |
| 多任务 dev AUC 平台中值 0.9970 | — | ~98 | **8.2×** |

**为什么"平台"这次站得住**：v4 的 dev AUC 是 ep5 见顶后**回落**，那像退化不像收敛。多任务这版 **dev AUC 在 ep9–ep19 连续 11 轮稳在 0.9963–0.9976，而同期卷积权重变化从 14.77% 推到 22.41%、实例 loss 从 0.4052 继续降到 0.3055** —— 损失还在降、特征还在变、排序质量就是不动。两个独立机制（纯实例 / 语义锚定）都停在同一带上。

**天花板本身也在涨，但涨不到可用**：test recall@0.5 从 0.096（冻结）推到 0.264（多任务）≈ 2.7×，可即便给了完美定位 + 真改造过特征，**仍只有约 1/4 的物体达到 IoU≥0.5**。

## 6. 语义 × 实例：可以共存（本轮唯一的正面架构结论）

- v4 用**实例**目标微调**语义预训练**的编码器，语义掉 28.3% ⇒ 该编码器不能插回完整模型（同一个编码器还要压 scene token 给 LM）。
- 加上 lidarseg 语义 CE 之后（与 v4 的唯一变量），编码器被改造的幅度更大（21.8% vs 19.97%），**语义反而小幅提升**（0.33109 vs 预训练 0.30785，+7.5%），且实例侧 test AUC / R@0.5 / IoU 三项都优于 v4。
- 且探针显示语义 miou 在 `dW conv` 从 8.67%→21.81% 的**全程平坦** ⇒ 两个目标不冲突，v4 的语义损失是"只有实例目标时特征被单向拉走"，不是必然代价。

⇒ **"让编码器适应实例目标"这条路现在是可用的**；它没有被证伪，被证伪的是"它能补上那 8–26 倍的排序缺口"。

## 7. 度量 bug 与可复现性陷阱（四项，全部已修或已标注）

1. **TF 分母模型相关**（`train_reasonseg.py:437`，修于 `a684511`）：原 `present = object_valid & union.gt(0)`，`union = ((pred|target) & valid)` ⇒ 触发越多的模型被塞进越多"物理上不可能命中"的物体进分母。改为纯数据口径 `scorable = object_valid & (target & valid).any(-1)`，并把 mean/global 的全局求和一并限制在 scorable 上。实测两侧 objects 精确变成 2297 = 2440−143。
2. **5.86% 验证目标物理不可达**：2440 个 target 里 **143 个**全部点落在 `point_cloud_range = [-51.2,51.2)²×[-5,3)` 之外（car 71 / truck 53 / bus 8 / barrier 5 / construction_vehicle 4 / trailer 2，点数中位 5 vs 保留物体 13），另 38 个部分越界。已定为**按记录过滤**（2,248→2,108 条）—— 按单个 target 摘除会让 query/answer/targets 三者失配、连带弄坏语言侧监督。实测过滤几乎不改结论（Δ 从 +0.00694 变 +0.00675）⇒ 结论对口径稳健。
3. **lidarseg mIoU 0.2876 不可复算，两个独立原因**：① `save_spatial_encoder_checkpoint` **只存 `point_encoder` 的 52 个张量，分类头从未保存** ⇒ "加载后直接验证"会用随机头静默算出垃圾数（同一份权重实测 0.19633 与 0.00706，取决于样本集；accuracy 0.895 只是塌到多数类的频率）；② `c51c644`（09-22）把 `split="val"` 从官方 val（**6,019 条**）改成官方 train 场景内防泄漏划分（**2,806 条**），而该档是 09-21 训的（日志每轮 28,000+ 步 = 官方 train 全量 28,130 为铁证）。⇒ 现行入口改为**线性探针**（`--validate-only`），并在输出里硬写 `comparable_to_recorded_miou: false`。
4. **接地诊断把"框内点数"当"前缀长度"**（修于 `cdc29b9`，Phase 2.3 裁定完才改，避免移动球门）：`point_count = point_valid.sum()` 后切 `[:point_count]`。实测越界点占帧内 6.18% 但**尾部集中度仅 0.0585**（散布，不在尾部）⇒ 前缀混入约 2,035 个概率恒 0 的越界点、同时丢掉尾部同样多的框内点，并把 2.42% 物体的 GT 截成空再被 `if target_size == 0: continue` **静默吞掉**（1,000 条本应 1,091 物体却报 1,068，也因此从不见 NaN）。
   **偏差方向曾被判反**：当时断言"AUC 被白送的简单负例抬高、真实值更低"。修好后三个档 AUC 全部**升高**（对照 0.8576→0.8755、A2 0.8371→0.8540、B1 0.9048→0.9252）—— 真机制是前缀把**越界的 GT 点当成了正例**（概率恒 0，注定输给所有负例），把逐物体 AUC 拽向 0.5（AUC<0.6 的物体从 116 个降到 68 个）。**只算了分母一侧、漏了分子一侧，符号就反了。** 裁定不变（缺口仍 203–338×），但"这个修复会加强结论"一句作废。

**另有一项 infra 坑**：`tar cf - .` 同步会把当前目录条目本身存进归档，以 root 解包时会把仓库根 chown 成归档里的 Windows uid ⇒ git 报 `detected dubious ownership`。修法是 `chown root:root`，**不是**加 `git config safe.directory`（那是掩盖问题）。

## 8. 方法学教训：预注册判据四次没覆盖住结果

| 次序 | 场合 | 症状 | 根因 |
|---|---|---|---|
| 1 | Phase 2.0 四条判据 | 阈值没能把结论分开 | 拿 `recall@0.5` 当判别量 |
| 2 | Phase 2.2 尺寸护栏 | PARTIAL 档无法裁定 | 同上 |
| 3 | oracle 探针首跑 | recall 0.045 判"特征瓶颈"，但 AUC 0.978 反驳 | **挑错轴**：recall 把"排序够不够好"与"幅值校不校得准"混成一个数 |
| 4 | 多任务五档分支 | 落在所有分支之外 | **不同于前三次**：五档全假设 miou 会下降，给"优于最好预期"留了零出口 |

已经固化的纪律：判别量按轴拆开（AUC / `recall_top_k` 免幅值 vs `recall@0.5` / 尺寸比 幅值）；门槛尽量**先验推导**（如 1−K/N、2K²）而非拟合观测；AND 条件标明主轴与次轴；**分支必须显式包含"结果优于预期"**；以及在看过数据后改判据时，必须声明是事后改的并给出与观测无关的推导来源。

另外两条同族的纪律，都是用 GPU 换回来的：**全新代码进串行链必须先过冒烟中止门**（Phase 2.3 的三个冒烟抓出过一个会**静默**返回错误结果的形状 bug 和上面那个前缀掩码 bug）；**消融测试要防空洞通过**（LOC 先验切除是一对测试：关闭态扰动必须零影响、开启态必须改变）。

## 9. 当前状态

**已定案**
- 七条杠杆判死（含机制）；瓶颈 = 实例接地，不是分割、不是损失、不是数据规模、不是语言侧。
- oracle 探针：**单帧点特征撑不起实例接地**（两个独立机制的 AUC 平台一致停在 0.995–0.9976）。
- 语义与实例目标**可共存**（多任务编码器语义不降反升）。
- `voxel_size` 不是杠杆：打分对象是原始 LiDAR 点 ⇒ N、K 与该旋钮无关；同体素并列实测 T 中位为 0、AUC 上限 0.99999996 ⇒ 那 100~300 个干扰负点全是真实的排序失败，不是表示退化。

**未定案 / 在跑**
