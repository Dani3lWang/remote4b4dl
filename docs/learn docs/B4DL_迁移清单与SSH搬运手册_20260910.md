## 0. 结论速览

代码已与 `origin/main` 同步（无未推送 commit），因此 **代码用 `git clone` 拿，只搬 5 个数据包（约 20G）+ nuScenes（按用途 0~55G 三档，见 §3）+ conda 环境（8.4G）**。

**不需要搬**：`sweeps/`（338G，全代码零引用）、其余 5 路相机样本（仅在重跑数据生成时需要，见 §3 批次 B 2 档）、`lidarseg`、checkpoint 里的优化器状态（约 5G）、roberta-large 的 4 种重复格式（13.6G）、`.claude/` 会话记录（601M）、`.ssh/`（含私钥，禁止外传）。

**搬运方式**：首选「源机 → 新机 直连 rsync/tar 流式」，不经本地盘；小文件（28,130 个 `.npy`）**必须先打 tar**。

**能下载就别搬**：Vicuna-7B（13G）、roberta-large（1.5G）、CLIP ViT-L/14（890M）、HF 发布的 B4DL 与 LiDAR-LLM 数据集，在 README 与 `docs/` 里都有官方下载入口，新机联网自行下载即可——清单与命令见 §3 末「可直接下载的清单」。

## 1. 容量汇总

| 批次 | 内容 | 体积 |
|---|---|---|
| A | 代码 + 基座模型 + 检查点 + 编码器 + 特征 + 数据 JSON | ~20G |
| A-env | conda 环境 `wqlc` | 8.4G |
| B | nuScenes 关键帧子集（**按用途分三档**：0 档不搬 / 1 档重提特征 30.6G / 2 档重跑数据生成 ≈55G，见 §3） | **0~55G** |
| C | 可选：训练日志 / 评测产物 / 备份包 | ~3G |
| **合计** | 不含 C | **~59G** |

新机建议：**数据盘 ≥200G**（需容纳训练工作区：merged 完整 7B 模型约 14G、`save_total_limit 3` 的滚动 checkpoint 约 6G；历史上未清理时 checkpoints 峰值曾达 145G），**系统盘 ≥30G**（若 conda 环境装系统盘则 50G+）。

> 批次 A 里 Vicuna 基座（13G）、roberta（1.5G）、CLIP ViT-L/14（0.9G）、两个 HF 数据集（0.4G）都能在新机直接下载。若新机网络良好，**真正需要搬运的 A 类内容只有约 5G**（自训编码器、特征、checkpoint、QA 数据、元数据）。

## 5. SSH 搬运方法

### 5.1 前置：密钥与连通性（源机执行一次）

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_migrate -N "" -C "b4dl-migrate"
ssh-copy-id -i ~/.ssh/id_ed25519_migrate.pub -p <新机端口> root@<新机地址>
ssh -p <新机端口> root@<新机地址> 'echo ok'          # 验证免密连通
```

AutoDL 的地址与端口在控制台「登录指令」里，形如 `ssh -p 12345 root@region-xx.autodl.com`。

### 5.2 方法一：源机 → 新机 直连（推荐，不经本地盘）

```bash
tmux new -s migrate                                   # 长任务防断线
ssh -p <新机端口> root@<新机地址> 'mkdir -p /root/autodl-tmp/transfer'
cd /root/autodl-tmp/transfer

rsync -avP --partial --append-verify -e 'ssh -p <新机端口>' \
    A2_base_model.tar A3_ckpt_encoder_data.tar A7_features.tar A8_clip_cache.tar \
    A10_roberta.tar A11_dataset.tar A14_logs_eval.tar B1_nuscenes_keyframes.tar \
    root@<新机地址>:/root/autodl-tmp/transfer/
```

- `-P` 显示进度，`--partial --append-verify` 支持断点续传（`scp` 没有断点续传，大包别用 `scp`）
- 大二进制包不要加 `-z`；跨地域带宽小时，只有代码/JSON 包值得压缩
- 本地临时盘不够时，可以边打包边流式传输，不落中转包：

```bash
tar -cf - -C /root/autodl-tmp/wql/mmb4dl mllm/base_model \
  | ssh -p <新机端口> root@<新机地址> \
    'mkdir -p /root/autodl-tmp/wql/mmb4dl/mllm && tar -C /root/autodl-tmp/wql/mmb4dl/mllm -xf -'
```

带宽参考：13G 的基座模型包，20MB/s 约 11 分钟，5MB/s 约 45 分钟。

### 5.3 方法二：经本地中转（Windows 本地仓库场景 / 两台机器互不可达时）

本机 `~/.ssh/config` 配两个 Host，之后命令只需写 `old` / `new`：

```
Host old
  HostName <老机网关>
  Port <老机端口>
  User root
Host new
  HostName <新机网关>
  Port <新机端口>
  User root
```

两段式传输（WSL 或装了 rsync 的 Git Bash；Windows 自带 Git Bash 通常没有 rsync）：

```bash
rsync -avP old:/root/autodl-tmp/transfer/ ./transfer/     # 第一段：老机 → 本地
rsync -avP ./transfer/ new:/root/autodl-tmp/transfer/     # 第二段：本地 → 新机
```

纯 `scp` 版本（无断点续传，适合小包）：

```bash
scp -P <老机端口> -r root@<老机地址>:/root/autodl-tmp/transfer ./transfer
scp -P <新机端口> -r ./transfer/* root@<新机地址>:/root/autodl-tmp/transfer/
```

图形化替代：WinSCP / MobaXterm 各开一个会话，两栏互拖。本地盘紧张时按包分批中转，不要一次性全拉。

### 5.4 方法三：两台都是 AutoDL 时

- **文件存储**：控制台「文件存储」支持多实例同时挂载，写一次两端可见，适合 20~30G 级别
- **直连试探**：把源机公钥追加到新机 `~/.ssh/authorized_keys`，在源机执行 `ssh -p <新机端口> root@<新机网关>`；能否直连取决于网关策略，先试探再选路线
- 也可以走控制台的「文件管理 → 上传/下载」做 10G 以下的小包

### 5.5 传完立即校验

```bash
# 新机执行
cd /root/autodl-tmp/transfer && sha256sum -c SHA256SUMS.txt
```

## 8. 坑与注意

1. **小文件必须先打 tar**：`b4dl/` 下 28,130 个 `.npy` 合计仅 333M，逐个 rsync 的元数据往返开销远大于数据本身。
2. **`.ssh/` 绝对不能搬/提交**：仓库内 `.ssh/` 放的是项目私钥（`id_ed25519_b4dl`、`.ssh_project`），已 gitignore。
3. **不要重下 nuScenes**：官方分卷把 samples 与 sweeps 混装（10 个 blob，约 400G），没有"只下关键帧"的选项——1 档 30.6G 子集只能从源机拷（2 档再加 5 路相机）。
4. **特征代次不可混用**：`*_once` 是 ONCE 旧编码器产物，与现行（nuScenes 自训 + 退火）不是一代；一旦改动编码器结构、`sst_encoder_only_config.py` 的几何参数或 `loader.py` 预处理，**所有 `.npy` 必须全量重提**（提特征脚本内置"加载不完整即拒绝"的 fail-fast 保护），且训练侧 `mm_projector`（`vtimellm_arch.py:12` 写死 `nn.Linear(768, hidden_size)`）需同步改并重训 stage1。
5. **checkpoint 可瘦身**：`ckpt_anneal/last.ckpt` 1.03G 中编码器只有 34MB；若要另存精简版，务必保留 `{"state_dict": {...}}` 外层包装——加载代码是 `ckpt["state_dict"]` 取键的。
6. **改动先分层**：改 mllm 侧（`dataset.py` 切片、prompt、metatoken 注入、评测规则、RL 奖励）不影响现有特征，旧 adapter 继续可用；改编码器/预处理则旧特征与旧 checkpoint 一起作废。
7. **搬运前确认已推送**：`git status -sb` 若出现本地 commit 未推送，先 `git push`，否则新机 clone 不到最新代码。
8. **迁移完成后再删源机数据**：建议新机验收通过（§7 全部通过 + B3 评测复现）后再清理源机 checkpoints/特征，避免两头落空。
9. **CLIP 权重有两份，别搞混**：提特征读的是 `~/.cache/clip/ViT-L-14.pt`（890M），而 `encoders/lidarclip/pretrained/ViT-L-14.pt`（922M）是历史实验副本、提特征路径从不读它（`encoders/lidarclip/README.md` 让你放到 `pretrained/`，与实际代码行为不一致，以代码为准）。自行下载后用 md5 `096db1af569b284eb76b3881534822d9` 校验。
