# B4DL 训练方法对比：论文 vs 复现（seqv3-mixed，2026-08-28）

> 依据：训练日志 `mllm/training_logs/stage2_full_seqv3_mixed_20260826_131938.log`（3,474 步全程打点）、
> 训练脚本 `mllm/scripts/run_stage2_full_seqv3_mixed.sh`、论文原文 §4.1/§4.2/§5.1（`docs/mmb4dl-md/mmb4dl.md`）。
> 配套数值对比文档：`B4DL_评测数值对比与问题清单_20260828.md`。

## 一、本次训练（seqv3-mixed）的训练方法

### 1.1 定位：混合训练

本次是流水线的 **4D LiDAR Understanding Stage**，采用**混合训练法**：论文官方 148K 训练集（stage2 简单任务 + stage3 复杂任务）**全量混合一次训完**，只挂**单个 LoRA**。

此前曾按官方仓库拆两段（stage2 简单任务 → LoRA merge → stage3 复杂任务续训新 LoRA），实测发生**简单任务格式漂移**：Phase B 长句生成格式覆盖 Phase A 的短答案格式，exact match 归零（acc 0.0001）。核对论文 §4.2 原文 "The model is trained on **both** Simple Tasks and Complex Tasks" 后确认**论文文字描述的正是混合训练**，官方拆两段只是实现选择 → 本次回混合法并叠加 seqv3 数据增量（commit `e94fd64`，决策详见 `B4DL_两阶段训练评测与混合法决策_20260826.md`）。

### 1.2 数据

- 训练集 `b4dl_dataset/stage2_full_train_seqv3_148k.json`：**148,271 条** = 简单任务 68,695 条（existence、binary_qa）+ 复杂任务 79,576 条（time_grounding、description、temporal_understanding、comprehensive_reasoning），其中 TG 13,124 条；699 训练场景，与 150 测试场景（30,145 条）零重叠。
- seqv3 增量（训练侧与评测侧完全一致）：
  - **TG 全部恢复 GT 序列归属**：benchmark 发布版丢失序列归属字段，从 GT 答案帧范围 100% 恢复（2,645 唯一 + 138 歧义）；
  - **真实帧 metatoken**：`ego_frame_motion.json` 逐帧运动表渲染，零 per-scene 回退；
  - **`feat_indices` 精确采样帧**：特征只取序列包含的帧，不混入非序列帧。

### 1.3 模型

- base：vicuna-v1-5-7b（6.74B，全冻结）；词表扩 `<4DLiDAR>`、`<meta>` 两个 special token（新 embedding 以旧词表均值/协方差的多元正态初始化），metatoken 两行 embedding（32000/32001）可训练，其余 embedding 行梯度掩码；
- 投影层：**95,048 条 nu-caption stage1 projector**（08-25 重训版：1 epoch、lr 1e-3、batch 16×8=128、742 步），本次 `--freeze_mm_mlp_adapter` 冻结；
- **LoRA r64 / α128**（attention + MLP），为全模型唯一可训练主体。

### 1.4 超参与工程配置

| 项 | 值 |
|---|---|
| 步数 | 3 epochs = **3,474 步**（日志确证；单进程一次跑完，无断点续训） |
| 学习率 | 1e-4，cosine，warmup 3%（日志：9.5e-7 升温 → ~1e-4 → 余弦衰减至 0） |
| 批大小 | 8 × 16 梯度累积 = 128 |
| 精度/并行 | bf16，DeepSpeed ZeRO-3，gradient checkpointing，单卡 5090 32GB |
| 正则 | weight_decay 0 |
| 序列长 | max 2048 |
| 保存 | save_steps 200、save_total_limit 3；结尾 `save_pretrained` 最终 adapter（320MB） |
| 其他 | `PYTORCH_CUDA_ALLOC_CONF=expandable_segments`，wandb offline，VTimeLLM v1 模板 |

### 1.5 训练过程（日志实录）

- 时间：2026-08-26 13:19 启动 → 08-27 12:14 正常退出（"Process 885593 exits successfully"），约 **23 小时**，与 CoRViD 训练共存一张卡。
- Loss 曲线（每步打点）：
  - step 1：loss **8.70**、grad_norm 53（LoRA 冷启动典型高值）；
  - 快速下降：step 50 → 2.19，step 100 → 1.50，step 200 → 1.41；
  - 平台期：**1.02–1.32**（step 300 起），grad_norm 稳定 0.5–0.8；全程最低 0.418（step 2318，短样本批）；
  - step 3,474：loss **1.126**，lr 衰减到 0。
- 收尾自动化：`run_mixed_eval_after_train.sh` 等 PID 退出 → 等最终 adapter 落盘 → 显存门控（空闲 <14GB 每 10 分钟重试；与 CoRViD 争用下前两次尝试 OOM/被 kill，第三次成功）→ HF offline 三件套（本机 huggingface.co 半开，不加必挂）→ 自动评测。

### 1.6 评测口径与结果（简述，详见配套文档）

- `evaluation/test_b4dl.py`：6 任务 × 7 指标；推理期注入 `<4DLiDAR> + <video> + question + <meta>`；`--per_sequence --frame_motion --sequence_metadata --answer_frames`；30,145 条全量、0 跳过（08-27 17:02 → 19:28）。
- 结果：**accuracy 0.7629**（论文 0.762）、**mIoU 0.2696**（历史新高）、BLEU-4 0.1080、METEOR 0.3344、ROUGE-L 0.3244、BERTScore 0.9734。

## 二、论文的训练方法（§4.1 / §4.2 / §5.1 原文）

### 2.1 模型三模块

1. **LiDAR 编码器 E_L**（LiDARCLIP 式）：voxelization + 传感器标定保证跨帧空间对齐；借助 CLIP（图像侧 ViT-L/14）做跨模态对齐，损失为 `L_similarity = (z_I − z_L)ᵀ(z_I − z_L)/d`——**仅正样本对**、无对比采样。每帧输出 `{p_cls, p_1…p_k}`，各帧 `p_cls` 拼接为 **4D LiDAR Embedding** 作为 LLM 输入模态。
2. **LiDAR Aligner f_p**：**单线性层**，把编码器输出投影进 LLM 文本嵌入空间（CLIP 只做高层语义对齐，粒度不足）。
3. **Metatoken `<meta>`**：原始传感器数值转成**相对上一帧的方向/位置/速度/加速度**文本（LLM 处理原始小数困难），只对**首帧与末帧**写文本描述，避免跨序列冗余。

### 2.2 两阶段训练管线

- **Stage 1（3D LiDAR Understanding）**：只用**静态 3D 点云**（LiDAR-LLM nu-caption 数据集，**162K QA 对**）；**仅 f_p 可训练**，E_L 等全部冻结；投影层因输入可拼接，也被训练得能处理下一阶段的 4D 拼接嵌入。
- **Stage 2（4D LiDAR Understanding）**：B4DL 数据集 **178K QA 对**（700 训练 / 150 测试场景，同源 nuScenes、同划分防泄漏）；**E_L 与 f_p 全冻结，只引入 LoRA**；输入 = 4D LiDAR Embedding + 与序列时空一致的 QA 对 + Metatoken；每个 QA 前加 `<4DLiDAR>` 前缀；**"The model is trained on both Simple Tasks and Complex Tasks"**；损失为**因果语言建模交叉熵**（文本 + LiDAR 模态联合训练）。

### 2.3 实验设置与未披露项

- LLM：Vicuna-7b-v1.5（训练/推理全程冻结）；编码器用 nuScenes 预训练；**单卡 RTX 4090、24 小时内训完**。
- 评测：每任务算指标再平均（accuracy = existence 与 binary_qa 平均；mIoU 仅用于 TG；复杂任务四项文本指标）。
- **论文全文未披露**：lr、epochs、batch、LoRA rank/α、精度、优化器、是否 ZeRO——超参细节只能继承官方仓库的 VTimeLLM 惯例。

## 三、对比

### 3.1 相同点（方法结构完全忠于论文）

| 维度 | 一致之处 |
|---|---|
| 两阶段结构 | stage1 只训投影层（静态 3D）+ stage2 只训 LoRA（4D 序列），对应 Figure 4 |
| 冻结策略 | E_L 与 LLM 全程冻结；stage2 冻结 f_p 只用 LoRA |
| 骨干 | Vicuna-7b-v1.5 |
| Token 注入 | `<4DLiDAR>` 前缀 + `<meta>` metatoken（首末帧运动描述） |
| 数据划分 | 700/150 分场景、同源 nuScenes；stage2 148K 训练 + 30K 测试 ≈ 论文 178K |
| 训练任务组织 | 混合训练（论文原文 "both Simple Tasks and Complex Tasks"） |
| 损失 | 因果语言建模交叉熵 |

### 3.2 差异点

| 维度 | 本次训练 | 论文 | 影响评估 |
|---|---|---|---|
| **stage1 数据量** | 95,048 条（≈论文 59%） | 162K nu-caption | **最大已知差距**：投影层欠训练 → 学到"场景级"而非"帧级"映射 → TG 无法区分帧号 |
| stage2 数据 | 148,271 条（TG 序列归属 100% 恢复、真实帧 metatoken、精确采样帧） | 178K，实现细节未披露 | 复现侧修复了发布版缺失；口径已对齐，论文侧实现未知 |
| stage2 组织 | 混合一次训完（论文文字） | 官方仓库拆 stage2/3 两段（实现选择） | 两段法实测崩坏（acc 0.0001）→ 混合法 acc 0.7629，验证论文文字正确 |
| 超参 | 3 ep / lr 1e-4 / batch 128 / bf16 + ZeRO-3（自选，对齐已验证的 seqv2 配置） | 未披露（官方仓库默认同款） | 差异不可判定，量级一致（单卡 <24h） |
| 硬件 | 5090 32GB，~23h | 4090 24GB，<24h | 无实质差异 |
| 评测 | 30,145 条全量 0 跳过；`--answer_frames` 用 GT 仅做输入帧/metatoken 选择（oracle，不进 prompt） | 未披露细节 | 口径差异已实测 ±0.02，非主要因素 |

### 3.3 结果对照（详见配套文档）

- accuracy 0.7629 vs 0.762：持平 ✅；BLEU-4 / METEOR / ROUGE-L / BERTScore 全线 ≥ 论文 ✅；
- mIoU 0.2696 vs 0.311（差 0.041）：历史新高但唯一未达标，根因证据链指向 TG 帧级定位未学会（先验拟合），首要嫌疑 stage1 投影层数据量。

## 四、结论

本次训练在方法结构上与论文完全同构（两阶段、冻结策略、LoRA、混合训练、token 注入、数据划分一一对应）。主要偏离仅两处：① stage1 投影层数据量只有论文 59%（最大嫌疑）；② 论文未披露的超参由官方仓库默认值承接（3ep、lr 1e-4，与论文单卡 24h 量级一致）。下一步：stage1 补数据至 ~162K → 重训 projector → 混合重训，目标 mIoU ≥ 0.30。
