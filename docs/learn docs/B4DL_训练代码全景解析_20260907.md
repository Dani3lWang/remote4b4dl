## 1. 训练代码总览

mmb4dl 有**两条彼此独立的训练主线**：

1. **VTimeLLM（MLLM 侧，`mllm/`）**：以 Vicuna-7B 为底座，把 LiDAR-CLIP 预提取的
   `(N_frames, 768)` 特征经 `mm_projector` 线性投影进 LLM 隐空间，用 LoRA 微调回答
   6 类 B4DL 时空问答。所有轮次的输出 token 在文本侧做**监督标签掩码**（只对答案
   计算 CE loss）。训练方法从"官方三阶段（stage1 对齐 projector → stage2 简单任务
   LoRA → merge → stage3 复杂任务 LoRA）"演进到仓库实际主力"stage1 + 混合 148k
   单 LoRA 3 epoch"（B0–B4a 基线链），入口脚本一族对应这一沿革。
2. **LiDAR-CLIP 编码器（`encoders/lidarclip/`）**：SST（LiDAR backbone）与冻结 CLIP
   的**图像-LiDAR 对齐训练**（MSE/余弦），PyTorch Lightning 实现，2026-08 在
   nuScenes 自训 + 短程退火，产出下游特征提取所用的最终编码器。

## 2. 启动脚本层

### 2.1 stage1.sh / stage2.sh / stage3.sh——三阶段配方

三份脚本结构相同：`deepspeed --include localhost:0 --master_port … train_mem.py` 加
一串超参，末尾 `"$@"` 允许追加命令行覆盖。以 stage1 为例（`mllm/scripts/stage1.sh`）：

```bash
MODEL_VERSION=vicuna-v1-5-7b
gpu_vis=0 # per_device_train_batch_size * gradient_accumulation_steps * n_gpus = 128
MASTER_PORT=29571

deepspeed --include localhost:$gpu_vis --master_port $MASTER_PORT vtimellm/train/train_mem.py \
    --deepspeed ./scripts/zero3.json \
    --model_name_or_path ./base_model/vicuna-v1-5-7b \
    --version plain \
    --data_path ./b4dl_dataset/stage1_train.json \
    --feat_folder ../encoders/lidarclip/b4dl/stage1_features_sample \
    --tune_mm_mlp_adapter True \
    --output_dir ./checkpoints/vtimellm-$MODEL_VERSION-stage1 \
    --bf16 True \
    --num_train_epochs 1 \
    --per_device_train_batch_size 16 \
    --gradient_accumulation_steps 8 \
    --save_steps 200 \
    --learning_rate 1e-3 \
    --weight_decay 0. \
    --warmup_ratio 0.03 \
    --lr_scheduler_type "cosine" \
    --model_max_length 2048 \
    --gradient_checkpointing True \
    --lazy_preprocess True \
    "$@"
```

三阶段的核心差异（`stage2.sh` / `stage3.sh` 同构，只列差异）：

| | stage1（对齐投影器） | stage2（简单任务 LoRA） | stage3（复杂任务 LoRA） |
|---|---|---|---|
| 基座 | vicuna-7b 原版 | vicuna-7b 原版 | stage2-**merged** 全量 |
| 模板 `--version` | `plain` | `v1` | `v1` |
| 数据 | stage1 描述（现役 `stage1_train.json` 161,629 条，LiDAR-LLM 派生、`sample_token` 键控，与 28,130 个特征文件逐键对齐） | stage2 简单任务 | stage3 复杂任务 |
| 特征 | `stage1_features_sample`（单帧 1×768） | `stage2_features`（整场景 N×768） | 同 stage2 |
| 微调开关 | `--tune_mm_mlp_adapter True`（**只训投影器**） | `--lora_enable True --freeze_mm_mlp_adapter True` | 同 stage2，但 `--model_name_or_path` 为 merged |
| epochs / lr | 1 / **1e-3** | 2 / **1e-4** | 3 / **2e-5** |
| LoRA | — | r=64, α=128, dropout 0.05 | r=64, α=128 |
| bs×accum | 16×8=128 | 8×16=128 | 8×16=128 |
| 保存 | 每 200 步（只存 projector） | 每 50000 步 | 每 50000 步 |

共同约定：bf16、tf32、`weight_decay 0.`、cosine + 3% warmup、gradient checkpointing、
`model_max_length 2048`、`lazy_preprocess`。**`weight_decay=0` 不是随便选的**——见
[5.5](#55-metatoken-embedding-行的梯度掩码) 的元 token 掩码约束。

### 2.2 zero3.json——单卡 28GB 显存跑 7B 的关键

```json
{
    "bf16": { "enabled": "auto" },
    "zero_optimization": {
        "stage": 3,
        "overlap_comm": true,
        "contiguous_gradients": true,
        "sub_group_size": 1e9,
        "stage3_gather_16bit_weights_on_model_save": true,
        "offload_optimizer": { "device": "cpu", "pin_memory": true },
        "offload_param": { "device": "cpu", "pin_memory": true }
    }
}
```

要点：

- **ZeRO-3 + 参数/优化器双 CPU offload**：7B 权重不在显存常驻，这是 5090（单卡、
  28GB 左右可用窗口）能训 7B 的前提，也是为何训练极慢、管线脚本要 72h 显存门控。
- `stage3_gather_16bit_weights_on_model_save: true`：保存时把分片参数聚合成完整
  fp16 权重，配合 train.py 里 `maybe_zero_3` 的显式 gather（见 5.8）。
- batch 相关全部 `auto`，由 HF Trainer 侧 `per_device_train_batch_size ×
  gradient_accumulation_steps` 决定。

## 3. 训练驱动器与自动管线

### 3.1 官方两阶段驱动器 run_stage2_full_seqv3.sh

论文/官方方法是"先简单后复杂、中间 merge"，驱动器把整条链做成了**幂等脚本**
（merged 存在即跳过 Phase A；两阶段各自支持 checkpoint 续训），供 cron/守护进程
安全重启：

```bash
MERGED=./checkpoints/vtimellm-$MODEL_VERSION-stage2-seqv3-merged

# ── Phase A: stage2 简单任务 ──
if [ ! -f "$MERGED/mm_projector.bin" ]; then
    echo "===== Phase A: stage2 简单任务训练（2 epochs, lr 1e-4）====="
    ...
    deepspeed ... vtimellm/train/train_mem.py \
        --data_path ./b4dl_dataset/stage2_train_seqv3.json \
        --output_dir ./checkpoints/vtimellm-$MODEL_VERSION-stage2-seqv3 \
        --num_train_epochs 2 --learning_rate 1e-4 \
        --save_steps 200 --save_total_limit 3 ...

    echo "===== Merge stage2 LoRA into base ====="
    python scripts/merge_stage2.py \
        --model_base ./base_model/vicuna-v1-5-7b \
        --pretrain_mm_mlp_adapter ./checkpoints/vtimellm-$MODEL_VERSION-stage1/mm_projector.bin \
        --stage2 ./checkpoints/vtimellm-$MODEL_VERSION-stage2-seqv3 \
        --output_dir $MERGED
fi

# ── Phase B: stage3 复杂任务（在 merged 上训练新 LoRA）──
deepspeed ... vtimellm/train/train_mem.py \
    --model_name_or_path $MERGED \
    --data_path ./b4dl_dataset/stage3_train_seqv3.json \
    --output_dir ./checkpoints/vtimellm-$MODEL_VERSION-stage3-seqv3 \
    --num_train_epochs 3 --learning_rate 2e-5 \
    --save_steps 200 --save_total_limit 3 ...
```

（`mllm/scripts/run_stage2_full_seqv3.sh:23-60` 节选）

### 3.2 B 系列混合单 LoRA 驱动器（B0–B4a 实际主力）

2026-08-26 决策后，基线链改为论文 §4.2 字面做法——简单+复杂任务**合并 148,271 条
一起训单条 LoRA**（`run_stage2_full_seqv3_mixed.sh`）。B1 之后各代是**拷贝上一代
驱动器、只改输出目录/数据文件/端口**的产物（B2 起加 `--whole_scene True`、B3 换
meta2 数据），因此脚本注释会残留上一代的标题——`run_stage2_full_seqv3_mixed_b3.sh`
文件头至今写着"B2 混合训练"，真实代际差异要看 `--data_path` 等实参。B2 驱动器
本体如下（B3/B4a 同构）：

```bash
# B2 混合训练（整场景输入，对齐官方 B4DL）：与 B1（run_stage2_full_seqv3_mixed_b1.sh）唯一差异
# 是 --whole_scene True——视觉输入不再按 QA 序列切片，而是喂整场景 (39/40/41, 768) 特征，
# 与官方实现（ccho4702/B4DL，dataset.py 对 np.load 结果直接用）一致。
# 动机：seqv3 的序列切片使 time_grounding 学会"序列局部帧编号"，评测按场景全局编号解析，
# mIoU 被系统性压低（B1 0.2653 vs 论文 0.311）；整场景输入下模型学到全局编号。
# 其余（数据 148k、162K projector、3ep、lr 1e-4、LoRA r64/α128、ZeRO-3）与 B1 完全一致。
...
RESUME=""
LATEST=$(ls -d ./checkpoints/$OUT/checkpoint-* 2>/dev/null | sort -V | tail -1)
[ -n "$LATEST" ] && RESUME="--resume_from_checkpoint $LATEST" && echo "Resume: $LATEST"

deepspeed --include localhost:0 --master_port 29582 vtimellm/train/train_mem.py \
    --lora_enable True \
    --model_name_or_path ./base_model/vicuna-v1-5-7b \
    --data_path ./b4dl_dataset/stage2_full_train_seqv3_148k.json \
    --output_dir ./checkpoints/vtimellm-vicuna-v1-5-7b-stage2-full-seqv3-mixed-b2 \
    --num_train_epochs 3 --learning_rate 1e-4 \
    --save_steps 200 --save_total_limit 3 \
    --whole_scene True \
    --report_to wandb \
    $RESUME 2>&1 | tee "$LOG"
```

（`mllm/scripts/run_stage2_full_seqv3_mixed_b2.sh`）各代驱动器的**全部实参差异**
只有 6 行（以 diff B2/B3 为例）：

```bash
echo "Data: ..._148k.json"              →  echo "Data: ..._meta2_148k.json"
export WANDB_PROJECT=...-b2             →  export WANDB_PROJECT=...-b3
OUT=...-mixed-b2                        →  OUT=...-mixed-b3
--master_port 29582                     →  --master_port 29583
--data_path .../stage2_full_train_seqv3_148k.json
                                        →  --data_path .../stage2_full_train_seqv3_meta2_148k.json
```

（B0 29580 / B1 29581 / B2 29582 / B3 29583 / B4a 29584；B0 无 `--whole_scene`，
B3 数据换 `meta2_148k`，B4a 换过采样 `150k`）

要点：`sort -V | tail -1` 取步数最大的 checkpoint 续训（与 train.py 内部逻辑一致，
见 5.7）；`--whole_scene` 是数据侧开关（见 7.2，训练与评测两侧各有一个同名开关）；
每个 B 系列独占 output_dir 与 wandb project，保证旧代产物不被污染、可随时对照复现。

### 3.3 B4a 全自动链：显存门控 + 判据化验收

`run_b4a_pipeline.sh` 是"训练-评测一条龙"的自动化样板：先等 GPU 显存 ≥28GB
（与 CoRViD 等项目共用 5090，72h 内每 10 分钟探测一次），训练结束后**不用日志
而用产物判据**（`adapter_model.safetensors` + `trainer_state.json` 的 `epoch>=2.99`）
确认成功，失败则自动断点续训重试 3 次；评测阶段再等 ≥14GB 窗口，5 次重试：

```bash
GATE_OK=0
for i in $(seq 1 432); do
    FREE_MB=$(nvidia-smi --query-gpu=memory.free --format=csv,noheader,nounits | head -1)
    if [ -n "$FREE_MB" ] && [ "$FREE_MB" -ge 28000 ]; then GATE_OK=1; break; fi
    echo "[$(date '+%F %T')] 显存不足 (${FREE_MB}MB < 28GB)，10 分钟后重试... (第 ${i} 次)"
    sleep 600
done
[ $GATE_OK -ne 1 ] && { echo "阶段1 显存门控 72h 未放行，链停止"; exit 1; }

for attempt in 1 2 3; do
    bash scripts/run_stage2_full_seqv3_mixed_b4a.sh > /dev/null 2>&1
    if [ -f "$OUT/adapter_model.safetensors" ] && [ -f "$OUT/trainer_state.json" ] \
       && python3 -c "import json,sys; d=json.load(open('$OUT/trainer_state.json')); sys.exit(0 if d.get('epoch',0) >= 2.99 else 1)"; then
        MIXED_OK=1; echo "阶段1 完成（尝试 #$attempt）"; break
    fi
    echo "阶段1 尝试 #$attempt 失败，10 分钟后断点续训重试..."
    sleep 600
done
```

（`mllm/scripts/run_b4a_pipeline.sh:22-42`）

评测阶段的命令行体现了"**口径冻结**"原则——与 B3 逐字节一致的评估参数：
`--whole_scene --per_sequence --answer_frames`，并当场打印与 B3/论文的差值
（ΔmIoU>0.013 才视为显著）。

## 4. 入口 train_mem.py 与运行时补丁

```python
# train_mem.py
# flash_attn 2.x 不支持 RTX 5090 (sm_120)，改用 transformers 原生 SDPA
# 需要 transformers >= 4.45
try:
    from llama_flash_attn_monkey_patch import replace_llama_attn_with_flash_attn
    replace_llama_attn_with_flash_attn()
except ImportError:
    pass  # flash_attn not installed, using transformers native SDPA

from train import train
```

（`mllm/vtimellm/train/train_mem.py:13-21`）——入口只做两件事：尝试把 LLaMA
attention 换成 flash-attn（失败则静默走 transformers SDPA），然后调 `train()`。
注释是硬件适配痕迹：官方 flash-attn 2.x 在 RTX 5090（sm_120）上不可用，因此本机
实际走原生 SDPA 路径。

**DeepSpeed no_sync 补丁**（`train.py:29-40`，import 阶段即生效）：ZeRO-3 梯度分区
下 accelerate 的 `no_sync`（梯度累积用的梯度同步抑制）不兼容——参数被分区后
`no_sync` 语义失效。补丁在 ZeRO-3 时直接跳过 no_sync（DeepSpeed 自己管理累积），
否则维持原行为：

```python
# Monkey-patch: ZeRO-3 gradient partitioning 与 accelerate 的 no_sync 不兼容.
# 当 DeepSpeed 自行管理 gradient accumulation 时，跳过 no_sync 是安全的.
import deepspeed.runtime.engine as ds_engine
_original_no_sync = ds_engine.DeepSpeedEngine.no_sync
@contextmanager
def _patched_no_sync(self):
    if self.zero_optimization_partition_gradients():
        yield
    else:
        with _original_no_sync(self):
            yield
ds_engine.DeepSpeedEngine.no_sync = _patched_no_sync
```

### 5.1 参数 dataclass

三个 dataclass 经 `HfArgumentParser` 合成 CLI（`train.py:55-102`）。注意两个
非 HF 原生的训练开关：

```python
@dataclass
class TrainingArguments(transformers.TrainingArguments):
    training_stage: int = field(default=2)
    ...
    lora_enable: bool = False
    lora_r: int = 64
    lora_alpha: int = 16
    lora_dropout: float = 0.05
    train_meta_embed: bool = field(
        default=True,
        metadata={"help": "Train the <4DLiDAR>/<meta> embedding rows during LoRA "
```

### 5.5 Metatoken embedding 行的梯度掩码

这是 B4DL 复现里最精巧的一处：`get_peft_model` 把基座全部参数 `requires_grad=False`
之后，**只放开 `<4DLiDAR>` 与 `<meta>` 两个 embedding 行**，再挂一个 backward hook
把其它所有行梯度清零——效果是冻结行与基座逐位一致，两行学习专属 embedding：

```python
# ── Make the B4DL metatoken embedding rows learnable (paper §4.1) ──
# get_peft_model froze every base parameter above; re-enable gradient
# flow for the two metatoken rows only. A backward hook zero-masks all
# other rows, so they stay bit-identical to the base model while
# <4DLiDAR>/<meta> learn dedicated embeddings. ...
# Requires weight_decay=0 (stage2.sh default) so the frozen rows are
# not decayed by AdamW; also assumes single-device ZeRO-3 as in the
# provided launch scripts (gradient hooks are not ZeRO-partition aware).
if (training_args.lora_enable
        and training_args.train_meta_embed
        and 'chatglm' not in model_args.model_name_or_path):
    _meta_ids = tokenizer.convert_tokens_to_ids(["<4DLiDAR>", "<meta>"])
    if all(i is not None and i != tokenizer.unk_token_id for i in _meta_ids):
        _embed = model.get_model().embed_tokens
        _embed.weight.requires_grad_(True)
        _mask_cache = {}

        def _mask_meta_token_grads(grad, ids=tuple(_meta_ids), cache=_mask_cache):
            key = (grad.device, grad.dtype, grad.shape[0])
            mask = cache.get(key)
            if mask is None:
                mask = torch.zeros(grad.shape[0], 1, device=grad.device, dtype=grad.dtype)
                mask[list(ids)] = 1.0
                cache[key] = mask
            return grad * mask

        _embed.weight.register_hook(_mask_meta_token_grads)
```

（`train.py:367-397`）隐含约束链（注释里写明，务必遵守）：

- `weight_decay=0`：否则 AdamW 会对"冻结行"做衰减，破坏逐位一致；
- **单卡 ZeRO-3**：梯度 hook 不感知 ZeRO 分区，多卡会出问题；
- 训练好的两行 embedding 通过 `non_lora_trainables.bin` 持久化（见 5.8），推理与
  stage3 由 `builder.load_lora()` 恢复。

```python
    """Select the QA's sequence frames from scene-level features.

    Priority (paper: model input S_L is the QA's sequence):
      1. item['feat_indices'] — the sequence's exact sampled frames
      2. item['feat_range']   — [s, e] inclusive range of the sequence
      3. frame numbers parsed from the question (legacy data files)

    if indices:

    return _slice_features(feat, first_frame, last_frame)
```

```python
    def __init__(self, lidar_encoder, clip_model, batch_size, epoch_size,
                 loss="mse", scheduler_max_lr=1e-3):
        ...

        for param in self.clip.parameters():
            param.requires_grad = False
        if loss == "mse":
            self.loss_func = F.mse_loss

        self.log("train_loss", loss.detach())
        return loss
```

step <26,375 不判停（再训满 1 epoch）；step ≥31,550 硬保底。数据源用
LossCSVCallback 的 CSV 而非 ckpt current_score（后者滞后）。

## 12. B0→B4a 训练配方沿革

| 代（驱动器） | 数据文件 | 视觉输入 | metatoken 口径 | 相对上一代的唯一变量 | acc / mIoU* |
|---|---|---|---|---|---|
| B0（mixed） | `seqv3_148k` | 序列切片（feat_indices） | 旧渲染（前向差分） | —（基线，95K-caption 版投影器） | 0.7629 / 0.2696 |
| B1 | 同 B0 | 同 B0 | 同 B0 | projector 换 **162K 重训版** | 0.7787 / 0.2653 |
| B2 | 同 B0 | **整场景 `--whole_scene`** | 同 B0 | 视觉输入不再切片 | 0.7649 / 0.1992 |
| B3 | **`meta2_148k`** | 整场景 | **meta2（relative-to-previous 修复）** | 训练数据 meta 口径 | 0.7526 / **0.3467** |
| B4a | **meta2 150k（TG 高帧段 ×2）** | 整场景 | meta2 | 过采样数据分布 | 训练中（09-07 epoch 2.04 / step ≈2390/3519） |

\* acc/mIoU 取自 `mllm/eval_results/<dir>/metrics.json`；文本指标（METEOR 等）存在
NLTK-2005 主口径与 Meteor-1.5 jar 参考口径的双后端差异，本表不列，详见
`B4DL_METEOR双口径溯源与评测规则_20260907.md`。

沿革注释（教训都在数字里）：

- **B0→B1**：162K 重训投影器（sample_token 键控特征）几乎不改变结果（mIoU −0.004）；
- **B1→B2 是反证**：假设"序列切片导致局部帧号错位"→ 整场景输入重训，结果 mIoU
  反而 0.2653→0.1992，61% 预测塌缩成先验区间 (000,008)——40 帧无锚点输入下模型
  学不会绝对定位，切片不是 mIoU 瓶颈（详见 `B4DL_B3整场景meta修复mIoU超论文_20260906.md` §2.2）；
- **B2→B3 定案**：唯一变量 = 数据换 `meta2`（`ego_text.py` 渲染从"首帧恒 at the
  starting position + 前向差分"修复为论文 §4.1 的 **relative-to-previous（相对前一帧）**
  语义），mIoU 0.1992→0.3467（**+0.147**，超论文 0.311）——**meta 渲染语义是 mIoU
  的第一瓶颈**；
- **B4a**：针对 B3 残余问题（TG 预测整体偏早 mean −3.9 帧；GT start≥25 高帧段占
  ~15% 而预测仅 4%）做条目级过采样 ×2，B3 配方其余不动。

公共配方（B 系列全代）：混合数据全量单 LoRA、3 epochs、lr 1e-4、cosine+3% warmup、
LoRA r64/α128、bs 8×16（=128/step）、bf16、**无 tf32**（自 seqv2-148k 起）、
wd=0、grad checkpointing、ZeRO-3+CPU offload、每 200 步存 3 份、断点自动续训、
`--freeze_mm_mlp_adapter True`（stage1 投影器冻结，只训 LoRA + 两个 metatoken
embedding 行）。

## 13. 理解这套训练代码的十个关键点

1. **"训什么"由 requires_grad 精确控制**：stage1 只放行 mm_projector；stage2+ 只放行
   LoRA 分支；metatoken 两行 embedding 用"整体放开 + backward hook 逐行清零"的
   掩码技巧单独可训（train.py:367-397）——不是冻结整个表，也不是整体解冻。
2. **保存物三件套**：`adapter_model.safetensors`（LoRA 分支）+ `non_lora_trainables.bin`
   （掩码 embedding 行）+ 评测/续训时由 `builder.load_lora` 恢复（含键前缀剥离）。
3. **word-embedding 行 = 权重**：`wd=0` 是 metatoken 掩码方案的硬约束（衰减会污染
   冻结行）；多卡/非单卡 ZeRO-3 下 hook 不分区感知，同样是硬约束。
4. **`<video>` 是融合枢纽**：文本分词时插 `-200` 占位 → 前向按占位把投影后视觉
   特征嵌入序列 → 视觉位置标签 `-100` 不参与 CE。模型"看"到的视觉 token 数 =
   该条 QA 的采样帧数（≤ 场景帧数）。
5. **帧号坐标系是最容易翻车的语义**：训练输入切片到"QA 所属序列"（局部帧号）会让
   TG 学到局部编号，而评测按场景全局编号判分（B1 0.2653 的教训）；B2 起整场景输入
   学全局编号。`feat_indices`（精确采样帧）优先于 `feat_range`（闭区间）优先于问题
   文本解析。
6. **训练-评测同源注入**：inject_metatoken / ego_text / test_b4dl 三方共用渲染代码，
   metatoken 文本逐字符一致；评测侧 `--answer_frames` 用 GT 恢复序列归属属于
   oracle 输入选择（报告需声明）。
7. **fail-fast 胜过静默容错**：特征预检秒级校验全部 scene_id；运行期 8 次失败即抛；
   checkpoint 缺 trainer_state.json 拒绝续训；数据脚本写前断言、写后校验。全部是
   对"共享 GPU 环境里烧几十小时后才发现数据坏了"的防御。
8. **断点续训是基础设施不是选项**：train.py 数值排序取最新断点 + shell `sort -V`
   对齐；stage1 专门瘦身成每步 mm_projector.bin；VTimeLLMTrainer 与 HF Trainer
   双轨（stage1 vs 其余）互不污染。
9. **ZeRO-3 需要三处适配**：入口 no_sync monkey patch（train.py:29-40）、保存前
   `maybe_zero_3` gather（含 AVAILABLE 分支防 free_param 断言）、stage1 不落全量
   checkpoint。任何"看起来多余"的补丁都有一次实际崩溃对应。
10. **训练配方沿革都有评测数字背书**：B 系列每代只动一个变量（projector/输入
    范围/meta 口径/数据分布），其余锁定，ΔmIoU>0.013 才算显著——读代码时把
    "变了一个变量"当作设计意图，不要当历史包袱。
