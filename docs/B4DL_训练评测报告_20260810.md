## 一、背景与初始问题

### 1.1 初始症状

运行冒烟测试（`test_b4dl.py --max_samples 50`）时，模型对所有 6 种任务均输出连续点号：

```
existence:          "............."
binary_qa:          ".........."
time_grounding:      ".................."
description:         "................"
temporal:            "................"
comprehensive:       "......."
```

### 1.2 根因排查

**直接原因**：推理时 `build_query()` 默认在 prompt 中注入 `<4DLiDAR>` token，但该 token 未被训练过。

```
训练格式:  <video>\n<question>
推理格式:  <4DLiDAR>\n<video>\n<question>    ← 多了未训练的 token
```

`<4DLiDAR>` 的 embedding 在模型加载时从均值随机初始化，模型从未在训练中见过此 token，导致注意力模式被干扰，输出退化为 token ID 29889（`.`）。

**修复**（commit `ed5e9e5`）：
- `build_query()` 的 `use_4dlidar` / `use_meta` 默认值改为 `False`
- 仅在显式提供 `--ego_meta` 时启用 metatoken

### 1.3 深层问题

修复点号 bug 后，复杂任务仍只输出 `"from frame 000 to frame 008."`：

**根因**：训练数据严重失衡

| 答案类型 | Stage2 训练数据 (54,901 条) | 占比 |
|----------|---------------------------|------|
| `"Yes."` | 24,968 | **45.5%** |
| `"No."` | 15,530 | **28.3%** |
| `"from frame X to frame Y."` | 7,552 | 13.8% |
| 短物体名 | 3,960 | 7.2% |
| 长描述 (>40 字符) | **8** | **0.01%** |

模型在训练中几乎没见过描述类答案，学到的最优策略是：不管什么问题，都说 `"Yes."` 或 `"from frame 000 to frame 008."`。

## 二、训练方案

### 2.1 方案选择

原论文采用两阶段训练，将全部 148K 数据统一用于 Stage2。当前仓库将数据拆分为 Stage2（简单任务 55K）和 Stage3（复杂任务 64K），但 Stage3 从未被训练。

**选择方案 A**：合并 Stage2 + Stage3 数据，对标论文重新训练 Stage2。

### 2.2 数据准备

```
合并: stage2_train.json (54,901) + stage3_train.json (63,821) = 118,722 条

合并后答案分布:
  Yes/No:         40,504 条 (34.1%)
  time_grounding:  7,595 条 (6.4%)
  长描述:          59,249 条 (49.9%)    ← 从 0.01% 提升到 50%
  短物体名:         4,472 条 (3.8%)
  其他:             6,902 条 (5.8%)
```

### 2.3 Metatoken 注入

两份数据中 `<4DLiDAR>` 和 `<meta>` 含量均为 0%。注入后：

```
注入前: <video>\n<question>
注入后: <4DLiDAR>\n<video>\n<question> <meta> The metadata of the first frame is '...' and the metadata of the last frame is '...'
```

ego_metadata 覆盖 559/559 个训练 scene（100%）。

### 2.4 训练配置

| 参数 | 旧训练 | 新训练 |
|------|--------|--------|
| 数据 | 54,901 条 | **118,722 条** |
| Metatoken | 无 | **含 `<4DLiDAR>` + `<meta>`** |
| Epochs | 2 | **3** |
| 总步数 | 1,072 | **2,781** |
| Learning Rate | 1e-4 | 1e-4 |
| LoRA rank | 64 | 64 |
| Batch Size (effective) | 128 | 128 |
| 输出目录 | `stage2` | **`stage2-full`** |

## 四、模型行为分析

### 4.1 任务区分能力 ✅

模型已学会根据问题类型切换输出格式：

| 任务 | 主要输出模式 |
|------|-------------|
| existence | 60% Yes / 14% No / 26% 物体名 |
| binary_qa | 63% Yes / 37% No |
| time_grounding | 98% `from frame X to frame Y` |
| description | 100% 长描述（平均 285 字符） |
| temporal | 55% 长描述 / 10% time_grounding / 35% 其他 |
| comprehensive | 95% 长描述（平均 127 字符） |

### 4.2 输出多样性

| 任务 | 不同开头数 / 总样本 | 最常见开头占比 |
|------|-------------------|---------------|
| description | 1,548 / 3,770 (41%) | 5.0% |
| temporal | 3,055 / 4,757 (64%) | 3.6% |
| comprehensive | 6,271 / 7,540 (83%) | 0.5% |

多样性良好，无单一模板主导。

### 4.3 典型错误模式

#### 错误 1：物体误判（BICYCLE → CAR）

- **根因**：训练数据中 CAR (1,178 次) 是 BICYCLE (101 次) 的 11.7 倍；且存在大小写不统一（`CAR.` vs `car.`）
- **方案**：数据清洗——统一大写格式 + class-balanced sampling

#### 错误 2：帧范围退化（92% = `[000-008]`）

- **根因**：`[000-008]` 是训练中最常见的帧范围（10.4%），模型将其作为安全默认值
- **方案 A（数据层）**：高频帧范围下采样
- **方案 B（模型层）**：注入 frame index embedding

#### 错误 3：肯定偏向（No 召回率 55%）

- **根因**：训练数据 Yes:No = 1.61:1
- **方案**：Balanced sampling

#### 错误 4：格式残留（temporal → time_grounding）

- **根因**：训练数据中部分 temporal 问题的答案格式实为 time_grounding
- **方案**：数据重分类——扫描 frame range 答案，正确归类

### 4.4 改善优先级

| 优先级 | 方案 | 预期效果 | 难度 |
|--------|------|----------|------|
| **P0** | 数据清洗（大小写统一 + 格式重分类） | 解决物体误判、格式残留 | 低 |
| **P1** | time_grounding 帧范围下采样 | 缓解帧范围退化 | 低 |
| **P2** | Yes/No balanced sampling | 解决肯定偏向 | 低 |
| **P3** | 帧号特征注入 | 根本解决帧范围定位 | 高 |
