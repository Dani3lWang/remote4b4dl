## 归档方式与可信度

这批归档**不是**用户 Windows 侧导出的 `.md` 原件（原件在 `E:\Download\`，服务器不可达），而是按会话 ID 用 Qoder 的 `read_chat_session` 只读接口重新取回正文后重建的。因此：

| 项 | 状态 |
|---|---|
| 用户消息 | 逐字保留（都很短） |
| 助手正文 | 逐字保留，但受接口字符预算限制，**超长处被截断并以 `[…截断…]` 显式标注**，未做任何补写或推测 |
| 工具调用 | 只记「工具名 × 次数 + 失败标记」，**不含工具输入输出**（接口默认不返回） |
| 更早历史 | 三个会话 `hasMoreBefore=true`，本窗口之前的轮次未导出 |

需要完整原文时，用文件头表格里的会话 ID 重新调 `read_chat_session`（可把 `maxOutputCharsPerItem` 提到 8000、`includeToolOutputs` 打开）。

每份归档末尾都有一段 **「本次归档补记」**：2026-09-25 在服务器上直接读盘核实的结果，用来把会话里"进行中/待出数"的悬空状态收口，并标注事后被推翻或被禁用的口径。补记与会话正文分开写，不与当时的表述混淆。
