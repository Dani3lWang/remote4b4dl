# upcore 开发方向

更新日期：2026-10-28。依据用户决定，本地主线由 `codex/b4dl-core-geometry` 更名为 `upcore`，目标调整为 **更新 B4DL 主模型及其完整实验链路**。

## 目标与范围

提高 B4DL 使用 LiDAR 证据回答问题的可靠性，完善数据、训练、推理和评测的可复现性。更新可涉及编码器与特征、跨模态投影、时序建模、语言模型接入和监督数据；具体结构与基座选择需要独立实验支持，本次未选择新的 LLM 或编码器。

保留六项任务：存在性判断、二元问答、时间定位、场景描述、时序理解和综合推理。时空理解仍是主模型能力的一部分；实例分割召回、点掩码和跨帧实例跟踪不作为 upcore 的默认目标或完成条件。

现有时序几何适配器是已有候选方案。训练完成性、六任务退化和输入证据利用需要分别验收，不能将几何 JSON 训练 loss 下降解释为整体升级成功。

| 范围 | 主要位置 | 当前职责与后续重点 |
| --- | --- | --- |
| 基底与模型接入 | `mllm/vtimellm/`、`b4dl_core/integration.py` | 基底恢复、视觉 token 展开、生成缓存、可训练参数和保存重载 |
| 主模型更新 | `b4dl_core/b3.py`、`temporal.py` | 受控适配、数值诊断及长任务恢复；结构变化使用独立实验版本 |

## 当前证据与限制

- 初次审查基于功能源码提交 `4a94042`；2026-10-28 依用户要求完成依赖、原子输出和推理恢复修复，模型结构与监督方法未改变。
- 修复后本地 `wqlc` CPU 核心检查共 81 项，79 项通过，2 项因缺 nuScenes/pyquaternion 跳过；不代表真实 GPU 数值稳定性或模型质量。
- 当前已实现真实特征干预、完整分母几何评测、输入身份核验、六任务回归入口及非有限损失现场保留。
- 最近已记录的 2026-10-26 远端核验为：A3/seed42 成功更新 4953/13851 次后失败，保存点 4750；开发集预测 4562/13602 条且无有效完成凭证。本次未重新查询远端状态。
- 当前实现摘要与旧冻结实验不一致，正式训练校验会拒绝直接沿用旧计划。后续恢复需要经过核验的迁移方案、新实验记录与独立输出。
- 历史 SST 输入使用 `CAM_BACK_RIGHT` 裁剪范围，几何监督已按实际支持修订。全视野输入需要重新提取特征并验证分布兼容性，不能只修改描述。

## 执行顺序

### 第一阶段：运行与结果可复现

1. 基础依赖与 CPU/CUDA、可选扩展分层及版本/API 预检已实现，短前向和核心检查通过；干净环境重建及 CUDA 验收仍待完成。
2. 原子输出、几何推理共同提交日志/`--resume-inference`、六任务尾行恢复和完成文件哈希核验已实现。命令及历史产物边界见 [环境与恢复说明](../../mllm/docs/upcore_runtime.md)。
3. 新增 22 项故障及兼容性回归全部通过；触发条件、初始复现和修复证据见 [代码审查](../research/upcore代码审查_20261027.md)。

### 第二阶段：主模型更新的比较依据

1. 对历史非有限损失开展有界 CUDA 诊断；核验输入、权重和下一步更新后，建立显式迁移或独立重训实验。
2. 完成 A0 与候选更新的同口径六任务比较，报告分项及退化；开发集前缀和训练 loss 不能代替全量结果。
3. 保留历史答案辅助协议；新增不依赖 GT 答案构造输入的自由推理协议。分别冻结、分别报告。
4. 运行已有置零、重复首帧、乱序和跨场景替换控制，结合选项轮换、严格相反标签配对与场景置信区间检查证据利用。继续披露可见范围、缺供体和历史数据暴露的限制。

### 第三阶段：依据回归结果选择更新方案

在完整比较后选择特征表达、投影/适配器、监督配比或语言模型兼容性等具体改进，每次明确输入、预算、对照和固定终点。防止六任务退化的监督混合或蒸馏属于候选方案，尚未实现或采纳。

## 完成条件与本次交付

主模型更新需要同时给出：可重建环境与资产身份、训练完成凭证、完整六任务及诊断结果、同口径对照与退化说明、可加载的独立模型产物。实验前定义需要改善的任务及允许回退范围；本次不预设未经确认的数值门槛。

本轮先完成本地分支改名、开发约定与入口文档调整和代码审查，随后修复确认的三项代码问题。当前实现身份随源码变化，历史冻结配置和权重保留；未启动训练或完整推理。远端分支未改名、推送或删除，本地暂保留原远端跟踪关系。

历史方法与验证证据继续维护在 [项目台账](../项目方法与落实情况.md)。
