更新日期：2026-10-18。代码分支：`4D_seg`，核对时 HEAD：`c970fc3`。依据为当前代码、本地实验交付及本轮重新连接 `connect.bjb2.seetacloud.com:32144` 后读取的 E2-C 完成记录。本轮只核对与调研，没有新增训练或推理。

**当前处于单帧空间分割的瓶颈诊断阶段。** 已建立可追溯的训练、推理、独立复算和案例审查流程；完整数据续训获得过有限改善，E1 已定位主要损失环节，E2-C 已完成但未通过采纳门槛。当前保留 epoch14 基线和 `NO_OBJECT=0.1`。下一步优先完成误检与标签审查，再选一个空间结构实验；语言绑定、跨帧关联和最终留出验收仍未完成。

## 1. 研究目标与实际进度

最终目标是让 B4DL 的回答对应到**唯一具体实例**，输出该实例在原始 LiDAR 点序上的掩码，并在后续跨帧保持身份。当前按三个可分别验证的环节推进：

| 环节 | 需要证明什么 | 当前状态 |
| --- | --- | --- |
| 空间掩码 | 找到目标点，正确区分类别和相邻实例 | MaskPLS 后端、训练、完整评测与独立审计已运行；当前召回仍低，未达到最终性能验收 |
| 回答绑定 | 自由生成回答中的指代能落到唯一实例，且能拒绝无目标情形 | 候选数据和引用审计已完成；人工确认绑定为 0，训练准入未通过 |
| 跨帧关联 | 同一物体在不同帧保持身份 | 有研究原型与路线；自由推理跟踪尚未验收，frame-local query ID 不能当作轨迹 ID |

官方 B4DL/B3 的问答路径与当前空间后端应分别报告。panoptic PQ、空间实例 Recall、语言指代 Recall 不是同一个指标；B3 的 `--answer_frames` 属于答案辅助输入选择，也不能据此证明自由回答绑定能力。

## 3. 已完成的训练与实验结论

### 3.1 完整数据续训带来有限改善

从 epoch11 / step2101 精确续训完整 764 帧，新增 3 轮、573 次更新，到 epoch14 / step2674。最终 TP 从 161 增至 188，Precision 从 36.84% 增至 41.96%，Recall 从 5.00% 增至 5.84%。该轮通过训练前设定的工程筛选，但仍是单种子开发集结果。

此前 16 帧优化子集上的两种损失改动没有通过筛选：正负各占 50% 的 BCE 使开发集小目标几何命中降到 0；有上限的平方根正点重加权也未获得合格收益。因此目前保留原 BCE，不优先重复盲目的正点加权。

证据：[完整训练预算对照](D:/Github/mmb4dl/training_logs/maskpls_autodl3_20261016/full64-budget-001/delivery/训练预算验证报告.md)、[损失修正验证](D:/Github/mmb4dl/training_logs/maskpls_autodl3_20261016/balanced-bce-capped-001/delivery/results/修正验证报告.md)。

### 3.2 E1 完成了固定权重诊断

E1 在 5090 环境完成 416 次主前向和 6 次额外真实帧验收，训练更新为 0；独立磁盘审计通过。epoch14 最终 TP=188，与原 4090 基线一致，支持本轮迁移后的诊断连续性，不能解释为换显卡提高算法性能。

| epoch14 开发集互斥归因 | GT 数 | 占全部 GT |
| --- | ---: | ---: |
| 没有几何合格候选 | 2,549 | 79.24% |
| 有几何候选但无正确类别候选 | 404 | 12.56% |
| 竞争后几何损坏 | 37 | 1.15% |
| overlap 过滤 | 39 | 1.21% |
| 最终成功 | 188 | 5.84% |

这里是逐目标的逆向归因。独立一对一匹配下的原始几何 TP=656、正确类别原始 TP=244、最终 TP=188，是三个不同统计；竞争有时也能修复原本不合格的候选，不能直接相减作为严格漏斗。

小目标的关键现象是**掩码纯度不足**。在 `no_geometry` 子集中，1–2 点目标最佳 query 的覆盖率中位数为 1、纯度中位数只有 0.00221；3–10 点分别为 0.667 和 0.037。部分目标点已被覆盖，但同时包含大量其他点。该观察支持研究实例分离与空间约束，还不能定位到某一个网络模块。

首层 attention 没有足够证据支持“普遍看不到目标”的解释，因此未执行可选的首层 full-attention 干预。细尺度格点纯净也不能证明骨干特征充分可分。E1 还发现 167 个训练探针目标的离线匹配 query 几何合格却预测 NO_OBJECT，为随后 E2-C 提供了动机；这些不是训练过程的历史匹配日志。

证据：[E1 正式报告](D:/Github/mmb4dl/training_logs/e1_5090_execution_20261017/E1诊断报告.md)。其中“下一步优先 E2-C”是当时建议，该实验现已完成，后续判断以本总结和 E2-C 报告为准。

### 3.3 E2-C 完成，但降低 NO_OBJECT 权重没有通过筛选

C0=0.1、C1=0.05，均从同一 epoch14 父权重出发、重置优化器与调度器，保持数据流、共享采样和其他配置一致。每臂 3 轮、573 更新，共 1,146 更新及 4,584 次训练帧呈现。960 次新评估加 F 的 160 帧缓存，共 1,120 帧通过独立审计。

| 96 帧开发集，3,217 GT | F：epoch14 | C0：0.1 | C1：0.05 |
| --- | ---: | ---: | ---: |
| 最终 TP | 188 | 230 | 229 |
| FP | 260 | 435 | 526 |
| Precision | 41.96% | 34.59% | 30.33% |
| Recall@IoU0.5 | 5.84% | 7.15% | 7.12% |
| 原始几何 TP | 656 | 715 | 741 |
| 正确类别原始 TP | 244 | 332 | 343 |
| 1–10 点最终 TP | 22 | 35 | 31 |

相对同期 C0，C1 新增 95 个命中、丢失 96 个，净 TP−1，FP+91。不能把相对冻结 F 多出的 41 TP 全归因于改权重，因为 C0 同样多出 42 TP。九项预设门槛有五项失败，两个新实验权重均未替换 F。

FP 增量中，“与所有 thing GT 无交集”增加 57，“高纯度、低覆盖碎片”增加 30。这些是描述性分型：无交集不自动等于真实背景或错标，碎片也可能伴随错类，当前还不能证明 query 竞争是新增 FP 的原因。

39 项 CPU 契约与双臂 CUDA 前反向检查通过。338 个注册参数张量允许梯度，337 个实际更新；`decoder.level_embed.weight` 在原生 forward 中未使用，两臂均保持父值，不是本实验差异。是否启用它需要核对上游并单独设计对照。

**本轮排除的是“在当前预算和协议下，仅将 NO_OBJECT 从 0.1 降到 0.05 就能获得合格改善”这一窄假设，不是所有分类方法。**

证据：[E2-C 正式报告](D:/Github/mmb4dl/training_logs/e2c_5090_20261018/E2-C分类实验报告.md)、[完成记录](D:/Github/mmb4dl/training_logs/e2c_5090_20261018/delivery/completion.json)。远端现场记录同样为 `full_e2c_complete=true`、`screen_passed=false`、`candidate_adopted=false`、`e3_started=false`。

## 5. 下一步决策与实验边界

**立即动作：保留 F，完成上述固定权重案例审查。** 审查优先回答新增前景属于真实目标碎片、stuff/忽略区、错误类别，还是标注与可见性疑点。不要继续下调 NO_OBJECT 来补救本轮失败，也不要用降低阈值换来的预测数增长代替效果提升。

审查后，只选一条训练分支。现有证据下，低改动候选是原方案的 **E2-Q：query 内容/空间位置初始化对照**，方法依据为 Mask3D；更强的空间约束可研究 P3Former。两者都旨在检验实例分离，但作用位置不同，不能合并在同一处理臂后归因于其中之一。

| 审查或诊断结果 | 后续候选 | 必须保留的限制 |
| --- | --- | --- |
| 主要仍是低纯度和邻近实例混合，未发现足以解释问题的标签异常 | E2-Q；或单独设计 P3Former 式位置约束 | 先选一项，不同时换骨干、损失、query 数和阈值 |
| 正确几何候选存在，但高分劣质掩码频繁挤占或保留 | 固定权重补采集后分析 score 与 mask 质量；必要时研究质量评分 | 现有 E2 二值掩码不足以精确重放竞争；GT IoU 只能用于诊断/训练监督 |
| 证据指向 thing/stuff 分工或语义 query 生成问题 | DQFormer 式分工的独立设计 | 当前尚未证实该机制；BEV、中心监督与融合模块需拆开，属于较大改动 |
| 特征/插值诊断显示远距目标表征不足 | 局部特征干预，之后才考虑 SphereFormer | 40m+ Recall 低本身不足以定位骨干瓶颈 |

E2-Q 原方案为三臂共同重置旧 query 历史：Q0 新可学习内容与位置；Q1 零初始内容、与 Q0 同初值的可学习位置；Q2 零初始内容、输入点 FPS 位置。保留相同父骨干及其他 decoder 参数，各 6 轮、1,146 更新，共 3,438 更新、13,752 次训练帧呈现。它尚未实现或运行；FPS 不能使用 GT 中心或类别。Q2 需超过 Q1 才支持位置采样策略，单独超过 Q0 不够。

下一项实验继续沿用预先固定的主要终点和同期对照：全部 TP 至少比最强控制/F 多 10；Precision 最多下降 2 个百分点；小目标最终 TP 不退步；结构实验的小目标几何 TP 至少增加 20，同时检查中/大目标、负区域与逐场景结果。完整定义以[原实验方案](D:/Github/mmb4dl/training_logs/experiment_design_20261017/实验方案.md)为准。若需要修订，应在运行前独立记载，不能依据终点结果放宽。

通过后才进入 E3：配对的后续训练种子重复，再用完整历史暴露清单排除已使用场景，固定真正留出集评测。当前 E2-C 未通过，E3 不启动。空间阶段稳定后再推进自由回答绑定与时序关联。

## 6. 阶段成果如何表述

可直接用于汇报：

> 本阶段围绕 B4DL 回答所指的具体实例，建立了保留小点数目标的 LiDAR 空间分割、独立审计与本机案例审查流程。在 64 场景训练、96 帧开发集上，完整数据续训将实例 TP 从 161 提升至 188，Precision 从 36.84% 提升至 41.96%。固定权重诊断表明，主要问题仍是几何候选不足，部分小目标虽被覆盖但掩码纯度很低；分类也存在候选转化损失。随后完成的 NO_OBJECT 权重对照没有通过采纳门槛，降低权重相对同期控制增加 91 个 FP、最终 TP 减少 1，因此保留原基线。下一阶段先完成人工误检与标签审查，再开展单因素 query 或位置约束实验。当前结果属于单种子开发筛选，语言绑定、跨帧跟踪及真正留出验证尚未完成。
