# upcore 代码审查（2026-10-27）

以 `4a94042` 的功能源码为依据，审查 `b4dl_core` 的训练、推理、存储与六任务评测，以及 VTimeLLM 接入和依赖声明。本地分支由 `codex/b4dl-core-geometry` 更名为 `upcore`。本轮交付为方向调整与审查，下面的功能问题尚未修复。

后续目标是更新 B4DL 主模型及其完整实验链路。实例分割、回答掩码和跟踪保留为历史研究及可选扩展，原有时空理解任务继续保留。完整范围见 [开发方向](../upcore/README.md)。

当前主线已有完整分母几何评测、真实特征干预、上下文长度拒绝、非有限训练保护及核心回归测试，本报告不将这些能力重复列为缺失。

## 1. P1：依赖声明与实际调用接口不兼容

位置：[requirements.txt](../../mllm/requirements.txt) 的 Transformers/PEFT/Torch 版本；[vtimellm_llama.py](../../mllm/vtimellm/model/vtimellm_llama.py) `forward()` 第 72–83 行。

主依赖锁定 Transformers 4.31.0、PEFT 0.4.0、Torch 2.5.1，当前 `forward()` 却无条件向父类传入 `cache_position`。本机保留的 Transformers 4.31.0 源接口经 AST 核对没有该参数，也没有接受未知关键字的 `**kwargs`。按旧声明建立环境后，这条调用会产生参数不兼容。当前本体测试实际使用 4.47.0 / 0.13.2 / 2.8.0+cpu。

主依赖还强制包含 flash-attn，与当前 SDPA 环境说明不一致；空间模块的 NumPy 约束需要独立处理。不能只替换几个版本号就宣称全部环境可复现。

建议：建立经过验证的 upcore 基础依赖与 CPU/CUDA 分层清单，增加版本/API 预检。验收覆盖干净环境导入、微型 VTimeLLM 前向/生成、保存重载及核心检查。本轮已修正文档中把旧 requirements 视为权威安装清单的表述，尚未修改依赖文件。

## 2. P1：几何推理重写文件可能损失已完成结果，且没有续跑入口

位置：[b3.py](../../mllm/b4dl_core/b3.py) `infer()` 第 337–373 行及 `main()` 第 416–417 行；[io.py](../../mllm/b4dl_core/io.py) `write_jsonl()` 第 34–37 行。

每个 batch 结束后，`infer()` 将累计的全部预测和输入回执分别以 `open("w")` 重写。中断落在重写过程中时，上一份完整文件已被截断；两个文件也没有共同提交边界，可能只写完其中一个。总重写记录量随请求数量呈二次增长。

运行身份 `run.json` 直到全部预测完成后才写入。中途失败后虽然已有部分预测，CLI 会因输出目录存在而拒绝继续，`--resume` 只用于训练。

本轮 CPU 合成复现：对真实 `write_jsonl()` 在第二条序列化处注入中断，原来保存 3 条的文件只剩 1 条；对真实 `infer()` 的第二批生成注入中断，第一条预测保留，但没有 `run.json` 或完成凭证，同目录再次调用 CLI 以退出码 2 拒绝。

建议：开始推理时固化运行身份，以稳定请求 ID 和输入指纹写入可恢复日志或原子分片，绑定预测与输入回执，原子发布完成清单。恢复必须拒绝不同权重、输入、解码或控制条件。验收包括中途终止、写盘中断、无重复/遗漏恢复及异实验拒绝。

## 3. P2：六任务续跑可能写出无效 JSONL 却标记完成

位置：[six_task.py](../../mllm/b4dl_core/six_task.py) 第 141–164 行；[io.py](../../mllm/b4dl_core/io.py) `read_jsonl()` 第 29–31 行。

恢复先按行解析旧文件，再直接追加。若最后一条是完整 JSON 但没有结尾换行，它能通过加载和 ID 检查，下一条却会紧贴其后，形成同一行的两个 JSON 对象。循环结束仍写出 `six_task_inference_complete`。若最后一条只写了一半，加载直接抛出 `JSONDecodeError`，完整前缀没有自动恢复路径。

本轮执行真实 `six_task.main()` 的恢复和写盘流程，协议读取、模型加载与生成使用显式 CPU 替身：1 条无尾换行的完整记录续写后，预期 2 条记录挤在 1 个物理行，重新读取报 `Extra data`，同时 `completion.json` 已存在。

建议：恢复前核验完整前缀、尾行及文件边界；补齐合法尾行换行，对残缺尾部保留现场并按明确规则恢复；完成前重读验证数量、唯一 ID、指纹和哈希。不能忽略中间损坏或身份错误。本轮没有修改已有预测文件。

## 4. 当前正式训练的阻断：新实现尚未形成受控恢复版本

位置：[experiment.py](../../mllm/b4dl_core/experiment.py) `validate_experiment()` 第 13–22 行；[integration.py](../../mllm/b4dl_core/integration.py) `load_checkpoint()` 第 206–223 行。

当前本地运行字节的实现摘要为 `f026ec053d1bf38b13425a4b92e4b48ed815e2987a223c0194b7a9ebd5e3b0b1`，历史冻结计划绑定 `aa072e07d5696d40d131999eb3e8377511ee0b333c7c779c328e8ea9ca51216f`。正式入口拒绝直接沿用旧计划，旧 checkpoint 身份也不能直接迁移到新实现。

这是已有保护的正确作用，不应删除校验或覆盖旧摘要。后续需完成数值诊断、有界 CUDA 核验、资产身份、数据顺序和迁移记录，再建立新实验版本。当前配置包含主机绝对路径，环境迁移还需显式材料映射与内容核验。

最近已记录的 2026-10-26 核验显示 A3/42 成功更新 4953 次后失败，保存点为 4750。CPU 有限回放和新增保护不能证明原 CUDA 非有限运算的根因已找到。本次未访问远端，不更新该历史快照。

## 5. 面向 B4DL 更新的评测与研究调整

[experiment.py](../../mllm/b4dl_core/experiment.py) `prepare_protocol()` 第 73–75 行固定 `answer_frames=True`，六任务结果明确标记答案辅助元数据。它可用于历史 B3 对照，实际输入条件还需要独立的自由推理协议。新增协议在构造输入时不读取 GT 答案，与历史答案辅助协议分别冻结、分别报告，已有协议哈希与历史结果保持原定义。

当前 SFT 使用几何 JSON 答案与证据，原语言模型冻结，主要训练 projector 和时序适配器。该方案需要同时验证描述、时间定位、综合推理等原任务，不能只看几何训练 loss。

优先完成 A0/候选更新的同口径六任务及真实输入干预，再依据退化选择监督混合、蒸馏、特征表达或基座接入等下一步。分割模块不是这条验收路径的前置条件，本次未选择或实现新的模型结构。
