## 2. 本轮已落实的改进

新增 [`inspect_core_progress.py`](../../mllm/scripts/inspect_core_progress.py)，用于独立、只读检查实验运行证据：

- 从 `runtime.json`、loss 日志、latest、作业 exit 和 completion 交叉判断训练状态，分别报告成功更新数、保存点和未保存更新数。确认完成时还核对 completion 哈希、检查点哈希、身份及预算。
- 在运行所属 Linux 主机上显式启用进程检查，核对命令、进程启动时间及僵尸状态，避免把复用 PID 当成原任务。读取迁回的回执时默认不查询本机 PID，只能得到未核验状态。
- 按实际推理使用的 `requests.jsonl` 获取几何完整分母；核对它在数据 manifest 中的哈希。核对六任务 protocol ID、请求文件哈希及 dataset ID。
- 检查预测的重复 ID、未知 ID、输入指纹、状态值、写入截断和读取期间变化。阶段完成必须同时有完整覆盖、匹配的 run 与 completion；仅有行数或 `running` 字段均不足。
- 输出各阶段覆盖率和状态，不计算前缀模型成绩、不接受模型效果。`controller_missing` 表示编排进程已失效，保留对子进程的判断边界。

脚本放在 `mllm/scripts/`，没有改动 `mllm/b4dl_core/`、模型、冻结配方或归档的云端脚本，不改变当前训练实现的哈希。现有 `8662e23` 与旧训练检查点之间的身份迁移要求仍然有效。

在运行所属主机的独立诊断目录使用：

```bash
python inspect_core_progress.py \
  --run-root /root/autodl-tmp/mmb4dl-core-sft-20261023-r1 \
  --dataset /root/autodl-tmp/mmb4dl-core-trainval-20261023-r1/trainval-v1 \
  --six-task-protocol /root/autodl-tmp/mmb4dl-core-sft-20261023-r1/protocol-v2/six-task-manifest-final.json \
  --check-local-processes
```

默认仅打印 JSON。`--output` 只允许创建新快照，不覆盖已有文件。本轮通过 SSH 标准输入实际执行，未写入或替换原远端部署。
