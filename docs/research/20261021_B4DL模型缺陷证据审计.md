## 1. 结论与缺陷优先级

当前最明显的问题，是语言回答与可验证的对象几何之间仍存在断层：B3 消费逐帧全局特征；MaskPLS 可以输出帧内候选，但候选质量较低，回答到唯一实例的训练数据尚未通过审核，也没有完成自由推理的跨帧身份关联。现有指标还不能排除模型依赖语言或答案先验。

| 优先级 | 缺陷 | 本轮证据强度 | 直接影响 |
|---|---|---|---|
| 高 | 空间候选生成及类别分辨率不足，尤其小目标、远目标和长尾类 | 最新开发集实验事实 | 即使后续选择器完全正确，也可能没有合格掩码可选 |
| 高 | 回答短语 → 唯一对象 → 点掩码没有完成学习和自由生成验收 | 当前代码、远端数据事实 | 语言回答正确不代表分割了回答所指对象 |
| 高 | 时间定位评测使用答案辅助的元数据范围 | 当前代码、隔离函数验证 | 成绩含 oracle 信息，不能代表无标准答案的部署条件 |
| 高 | `--no_4dlidar` 仅删除文本标记，不能构成无传感器对照 | 当前代码、隔离函数验证 | 容易错误归因模型是否利用点云 |
| 高 | 缺特征及推理失败被跳过，未作为失败项保留在主分母 | 当前代码事实，影响量未测 | 一旦发生失败，成功样本上的成绩可能偏高 |
| 中高 | 语言输入缺少显式对象级几何和可学习的点级反馈通路 | 当前架构事实；效果因果未验证 | 多实例消歧、距离排序、关系判别缺少直接证据接口 |
| 中高 | 4D 跟踪未完成；现有记忆原型使用 GT 身份赋值 | 当前代码事实 | 同一对象跨帧身份不能由帧内 query 编号保证 |
| 中高 | 无目标、不可见、指代不清与候选漏检尚无完成的拒答学习闭环 | 数据准入和接口事实 | 可能把空间漏检误当成物体不存在，或在证据不足时继续回答 |
| 中 | 内部开发集反复暴露，当前峰值为事后挑选；泛化证据不足 | 实验记录事实 | 不能把开发集最高点当作最终泛化成绩 |

## 2. 空间质量：最新结果仍不足以支撑可靠回答定位

采用同一 96 帧、8 场景、3217 个 GT 实例-帧；最终 TP 要求类别正确、原始有效点上的 mask IoU ≥ 0.5，执行一对一匹配。

| 权重 | TP / GT | FP | Precision | Recall@0.5 | 性质 |
|---|---:|---:|---:|---:|---|
| F epoch14 | 188 / 3217 | 260 | 41.96% | 5.84% | 当前正式保留基线 |
| P0 epoch04 | 282 / 3217 | 421 | 40.11% | 8.77% | 事后观测最高 Recall/F1，中途峰值 |
| P0 epoch06 | 272 / 3217 | 476 | 36.36% | 8.46% | 预先固定终点 |
| P2 epoch06 | 241 / 3217 | 489 | 33.01% | 7.49% | 位置残差未通过采纳门槛 |

P0 epoch04 仍漏掉 **2935 / 3217 = 91.23%** 的目标。它的原始 query 几何一对一匹配为 **739 / 3217 = 22.97%**；要求类别正确后为 345 / 3217 = 10.72%；最终输出为 8.77%。这说明候选几何不足和类别/选择损失同时存在。不同阶段会重新匹配，不能直接把数量差解释成同一批目标逐级流失，也不能据此断定骨干、attention 或体素尺寸就是根因。

| P0 epoch04 分层 | GT 数 | TP | Recall |
|---|---:|---:|---:|
| 1–10 点 | 1938 | 52 | 2.68% |
| 11–49 点 | 793 | 84 | 10.59% |
| 50+ 点 | 486 | 146 | 30.04% |
| 距离 40 m 以上 | 420 | 12 | 2.86% |

小目标占 GT 的 60.24%，却只有 2.68% 召回。类别上，汽车 215 TP、行人 62 TP，共占全部 282 TP 的 98.23%；护栏、自行车、公交车、工程车、摩托车、挂车六类在这一开发集上没有最终 TP。该结论限于此权重和开发集，不能外推这些类别在所有场景都无法识别。

本轮直接复算 F/P0/P2 的计数和 Precision/Recall，并通过 SSH 核对远端 P0 epoch04 指标文件的 SHA-256 与本地一致。服务器 E2-P 工作流仍记录退出码 0、阶段 completed；它证明实验执行完成，不证明性能通过。

已有控制实验限制了下一步解释：E2-C 将 no-object 权重由 0.1 降为 0.05，FP 从 435 增至 526，TP 230→229；E2-Q 的 FPS 未通过全部采纳门槛；E2-P 的 P2 相对同期 P0 少 31 TP，12 项门槛中 8 项失败。因此，继续降低阈值、降低 no-object 权重，或者直接采用当前位置残差，都缺少现成的支持证据。

## 3. 语言与对象之间：目前主要是全局特征接入，尚无完成的实例绑定

### 3.1 逐帧全局特征保留了什么，又缺少什么

`AttentionPool2d.forward` 默认以一个 query 汇聚空间特征，返回每帧向量；提取器在 `torch.no_grad()` 下计算并保存 `.npy`，按帧拼接为 `[T,768]`。B3 数据集加载这些离线特征，`vtimellm_arch.py` 使用 `Linear(768, hidden_size)` 将其插入语言 token 序列。语言模型仍可利用帧顺序和隐含空间语义，但此接口没有为每个对象显式提供实例 ID、中心、点掩码和轨迹。

当前 B3 训练使用语言模型的回答 token 监督；离线 `.npy` 也切断了回答损失直接优化 LiDAR 编码器的通路。不能把语言 loss 下降解释成点级实例辨别能力提高。**这是接口与训练目标的结构性限制；本轮没有通过消融证明它造成了多少关系错误。**

代码：[attention_pool.py](D:/Github/mmb4dl/encoders/lidarclip/lidarclip/model/attention_pool.py:46)、[特征提取](D:/Github/mmb4dl/encoders/lidarclip/extract_pc_features.py:102)、[投影接入](D:/Github/mmb4dl/mllm/vtimellm/model/vtimellm_arch.py:12)、[语言前向](D:/Github/mmb4dl/mllm/vtimellm/model/vtimellm_llama.py:66)。

### 3.2 有对象导出接口，不等于已经学会回答指代

`resolve_answer_objects(records, selected_ids)` 只校验外部提供的 ID 是否属于当前候选，并返回对应记录；它不读问题或回答来决定选哪个对象。对象导出明确保存 `grounding_verified=false`。Grounded4D 的 `reference_features` 对齐头是另一条原型路径，不能视作 B3 自由生成回答隐藏状态已经接入并训练完成。

远端本轮重新读取的绑定数据审计仍为：训练候选 14411、内部开发候选 1925；审核通过的训练/开发绑定均为 **0**，两个绑定 JSONL 文件均为 **0 字节**。候选的回答来源是数据集 GT，而非当前 B3 的自由生成结果。保留 pending 的准入机制是合理的，缺口是尚无可训练、已验收的语言绑定集合。

因此，目前不能宣称实现了“问题 → 自由回答 → 回答中的唯一实例 → 对应点掩码”。仅依据类别命中、最近对象或唯一同类候选自动绑定，仍可能把监督造错。

代码与数据：[objects.py](D:/Github/mmb4dl/mllm/maskpls_b4dl/objects.py:28)、[Grounded4D 对齐头](D:/Github/mmb4dl/mllm/grounded4d/model.py:106)、[绑定数据说明](D:/Github/mmb4dl/datageneration/docs/answer_binding_dataset.md)、[远端核验快照](D:/Github/mmb4dl/training_logs/research_audit_20261021/remote_verified_snapshot.txt)。

## 4. “4D”与拒答：两条尚未验收的能力

### 4.1 输入多帧，并不自动得到稳定对象轨迹

MaskPLS 数据加载器明确只接受单帧；对象 ID 为 `sample_data_token:q{query}`，`track_id=None`。这个 ID 在单帧内有意义，跨帧的 query 17 没有必然的物理身份对应。

Grounded4D 确实有 TrackMemory 和位置/速度外推，但 `update_memory` 根据 Hungarian 分配和 GT `instance_tokens` 写入身份，训练验证协议明确是 `teacher_forced_gt_track_assignment`。它可以用作监督诊断，尚不能证明自由推理中的关联、遮挡恢复或 ID 持续性。

后续需要从预测出发建立关联，并单独验证身份切换、关联质量和带掩码轨迹；不能用单帧 Recall 或 teacher-forced loss 代替。相对运动还应区分 ego 坐标变化与对象真实运动；本轮没有证据证明当前模型已学到正确的几何分解。

代码：[单帧准入](D:/Github/mmb4dl/mllm/maskpls_b4dl/data.py:46)、[空轨迹 ID](D:/Github/mmb4dl/mllm/maskpls_b4dl/objects.py:24)、[GT 身份记忆](D:/Github/mmb4dl/mllm/grounded4d/model.py:113)、[teacher-forced 验证](D:/Github/mmb4dl/mllm/grounded4d/train.py:72)。

### 4.2 MaskPLS 的 NO_OBJECT 不能替代语言层的无目标判断

MaskPLS 的 no-object 类监督的是“这个 query 没有匹配到 GT 掩码”，并不等于“用户问的对象不存在”。当前空间准备器排除 ROI 内没有 Thing 的帧；绑定候选缺失也可能来自 ROI、稀疏点、帧缺失或漏检。单靠候选为空直接回答 No，会混淆这些情况。

需要区别物理不存在、传感器不可见、空间后端漏检、指代歧义和证据不足。Grounded4D 虽有 no_referent 参数，但本轮没有完成的语言拒答训练与校准证据。不能由一个 no-object 参数推断系统已经解决幻觉。

代码：[空 Thing 帧拒绝](D:/Github/mmb4dl/mllm/grounded4d/prepare.py:164)、[绑定准入边界](D:/Github/mmb4dl/datageneration/docs/answer_binding_dataset.md)、[MaskPLS 类别定义](D:/Github/mmb4dl/mllm/maskpls_b4dl/config.py:14)。

## 5. 当前评测中三个可以明确定位的问题

### 5.1 默认时间定位有答案辅助信息

`run_baseline_eval.sh` 默认传入 `--whole_scene --per_sequence --answer_frames`。`whole_scene` 确实让点云特征不裁剪，但 `build_query` 对没有显式帧号的 time_grounding 问题仍可从 GT 回答解析首尾帧，并据此选择 ego-motion 描述。答案文本没有直接出现在提示词里，元数据选择过程却受答案影响。

本轮隔离执行真实 `build_query` 与帧解析函数，并用一个仅返回所选范围的 renderer stub：保持问题相同，改变 GT 的帧区间，生成的元数据范围随之变化。这验证了控制流，不是实际神经推理实验。结论应写作“答案辅助评测”；其对分数影响多大尚需同权重配对实验。

代码：[默认入口](D:/Github/mmb4dl/mllm/run_baseline_eval.sh:30)、[答案范围回退](D:/Github/mmb4dl/mllm/evaluation/test_b4dl.py:328)。

### 5.2 `--no_4dlidar` 不是无 LiDAR 推理

该参数只控制 `parts.append('<4DLiDAR>')`；随后始终插入 `<video>`，推理时仍传入 `feat_used`。本轮直接执行真实 `build_query`，验证两种结果仅相差 `<4DLiDAR>` 字符串，均保留 `<video>`。

因此这个参数适合“提示标记消融”，不能充当 question-only、zero-feature 或 shuffled-feature 对照。需要另外实现并记录实际特征干预；移除 `<meta>` 则是另一种干预，不能混为一项。

代码：[提示构造](D:/Github/mmb4dl/mllm/evaluation/test_b4dl.py:314)、[实际特征推理](D:/Github/mmb4dl/mllm/evaluation/test_b4dl.py:639)；验证：[no_4dlidar_probe.json](D:/Github/mmb4dl/training_logs/research_audit_20261021/no_4dlidar_probe.json)。

### 5.3 运行失败可能改变主分母

特征加载异常和推理异常均执行 `skipped += 1; continue`，只有成功样本被追加到预测和 GT 列表。现有 accuracy 用 `len(predictions)` 作分母。因此一旦有运行失败，主结果实际变成成功子集上的条件成绩。应保存全部请求 ID、失败状态、原定分母，并同时报告全量成绩与成功率。

这与时间区间解析失败是两件事：当前 `compute_miou` 已将不可解析区间计为 0，本轮没有把它错误地列为尚未修复的问题。也未测定你已有 B3 结果中实际跳过了多少条，故不能声称历史分数已被证实虚高。

代码：[缺特征跳过](D:/Github/mmb4dl/mllm/evaluation/test_b4dl.py:604)、[推理失败跳过](D:/Github/mmb4dl/mllm/evaluation/test_b4dl.py:641)、[指标分母及区间处理](D:/Github/mmb4dl/mllm/evaluation/evaluate_model.py:347)。

## 6. LiDAR-Hallu 的发现如何映射到你的模型

外部仓库是 B4DL 衍生模型的诊断基准，包含 150 场景、10000 个独立问题、两个模型配置和各五种条件的 100000 条保存预测。四种 prompt/metatoken 导出并不是 40000 个独立问题。NoMeta/Meta 使用分别训练的 checkpoint，不能解释成你的 B3 只改一段提示词的对照。

| 外部已保存结果 | 可以提示你检查什么 | 本轮不能据此宣称什么 |
|---|---|---|
| Temporal 默认 2000/2000 均选 A，accuracy 24.15% | 选项位置坍缩；需要选项重排和内容似然诊断 | 你的 B3 也必然总选 A |
| Distance 默认约 99.3% / 98.5% 选 A | 词面输出与几何关系是否脱节 | 已证明你的距离推理完全无效 |
| Left/right 正样本 145+157=302，两个模型默认 TPR 均为 0 | 关系正例召回；accuracy 可能掩盖全答 No | 你的 checkpoint 的 TPR 也是 0 |
| 不看传感器、按候选跨度的控制得 69.30% temporal | 候选生成存在可利用的统计捷径 | 69.30% 是当前 B3 移除 LiDAR 后的成绩 |
| Existence binary 66.30% / 67.20% 高于固定答案 50% | 证据利用可能随任务显著变化 | 所有 B4DL 系模型完全不看点云 |

主表 NoMeta/Meta overall 为 36.65% / 36.21%，需要结合预测分布、TPR/FPR 和固定答案超额收益阅读。**这些数字只属于外部归档模型。** sensor-free categorical control 使用其他评测场景的标签做交叉拟合，是套内先验可预测性诊断，不是当前模型的无点云推理，也不是等监督训练的神经基线。

当前语言评测主要报告答案匹配、时间 IoU 和文本相似度，没有形成覆盖上述问题的标准配对诊断。它们可衡量回答质量，但不足以独立证明几何证据利用。MaskPLS 候选接入本身也不会自动消除答案位置偏置或候选跨度泄漏。

## 7. MaskPLS 论文对当前路线的具体启示

译文第 3–5 页的关键机制是：多尺度稀疏特征、逐点位置编码、体素到原始点的插值、可学习 queries、逐层 mask 监督、Hungarian 匹配、BCE/Dice 和类别监督。它为你的空间实例路线提供依据，但论文任务是单帧全景分割，不能直接提供回答指代或跨帧跟踪。

当前 `maskpls_b4dl` 已保留 Minkowski 多尺度骨干、3 scales × 3 blocks、256 维 query、插值、位置编码和语义辅助头。不能再把早期 Grounded4D 的浅层单尺度原型缺点直接套到当前 MaskPLS 后端。

仍需明确的适配差异包括：当前单卡 128 queries，官方冻结推理 100；损失/匹配采样预算不同；当前默认没有随机几何增强，论文第 6 页使用旋转、翻转、缩放、平移；上游强度预处理与权重的一致性尚未完全证明。对语言几何任务加入增强时，还必须同步处理方向语义、ego 坐标和点序，不宜直接复制视觉增强。

此外，你保留 1 点实例，不使用上游约 50 点的 FP/FN 排除；当前指标是类别正确的实例 Recall/Precision，论文 nuScenes PQ 57.7 是另一协议。不能拿 57.7 与本地 8.77% 做倍数比较。训练规模、预算、增强和预处理差异是复现与泛化缺口，尚不是已被单变量实验证明的低召回根因。

## 8. 建议执行顺序与验收条件

第一步先让当前结果可解释：以同一 B3 权重、问题、候选顺序和解码设置，记录真实特征干预，去掉答案辅助元数据作为自由推理主口径，保留 oracle 结果作辅助上界；所有运行失败保留在原定分母。这一步属于评测修正，不是新的训练方案。

**唯一优先的模型诊断**：冻结 P0 epoch04，在同一 96 帧上对每个 1–10 点目标记录“是否存在 IoU≥0.5 候选、候选类别/NO_OBJECT、后处理去留”，按场景、类别、距离汇总。当前 raw geometry Recall 只有 22.97%，因此优先定位候选生成和实例分离；不要先扩大语言联合训练。三阶段需要逐目标对齐，避免用三个总体数相减制造因果结论。

之后根据该诊断选一个结构变量，并沿用同期控制、固定终点与独立审计；先建立新的留出场景，再做多种子验证。不得根据开发集反复选出的最优轮次直接宣布采纳。

空间能力改善的同时，可先审核少量单帧绑定记录，覆盖同类多实例、方向/距离/运动消歧及证据不足；冻结两端训练可拒绝的对象选择器。验收必须来自自由生成回答，分别报告答案、唯一实例绑定、点掩码及三者联合成功率。完成后再推进由预测建立的跨帧关联。

语言诊断至少包含：固定答案/类别先验、选项重排、同问题相反标签配对、真实特征干预、逐关系 TPR/FPR、按场景 bootstrap 区间。特征置零、乱序和跨场景替换各自改变的信息不同，必须分别解释；TSCD 的对比解码也不能替代直接的输入干预。
