# E2-C：固定数据流的NO_OBJECT分类对照

依据E1固定权重诊断选择本实验；这是暴露开发集上的单种子工程筛选，不是新留出测试。两臂模型架构与初始化相同，只改分类交叉熵中的`no_object_weight`：C0=0.1、C1=0.05。匹配代价、其他损失、query、输入、阈值均不改。

方法来源：[DETR，ECCV2020](https://arxiv.org/abs/2005.12872)的集合匹配和no-object加权分类；0.05和3轮预算是本项目假设，不是论文最优值。更改该权重也会改变加权交叉熵的归一化分母，这是预期的权重敏感性实验。

`scripts/run_maskpls_e2c.py`按prepare→smoke→run→audit→finalize执行。所有Python使用已验证的wqlc环境，生产模型需要匹配显卡的MinkowskiEngine/KeOps CUDA扩展。

- 精确加载SHA256锁定的epoch14模型，不能加载父优化器；新建两套AdamW/StepLR，lr1e-4、wd0.01、batch1、accumulate4、clip1、FP32。每臂3轮、573更新、2292帧呈现。
- prepare固定每轮764帧顺序，提前在CPU生成全部2292组匹配/损失采样点；两臂读取同一NPZ及hash，模型随机状态不能改变采样。显式采样仍检查合法点、唯一性和每个GT的前景覆盖。
- 复用E1首遍epoch14的160帧缓存，统一复算共同F。第0轮两臂的前向模型完全相同，不重复前向。原始候选与最终输出均使用固定SciPy最大基数、再最大总IoU的匹配归属，原生Hungarian独立确认基数。
- 两臂各新增3×(64训练探针＋96开发集)=480次评估，共960次；真实帧CUDA smoke额外2次，只有前反向，不执行优化器更新。
- C0 smoke在完全相同的真实张量和采样点上与父criterion逐分量比较；C1只允许classification变化。两个初始化state_dict指纹须相同，两个真实前反向梯度须有限。
- 每轮保存checkpoint及固定范围评估，不挑中途最好；每臂连续两个预定点发生低于F一半的最终TP或小目标几何TP时提前停止并记失败。非有限loss/梯度、数据/代码身份不符立即失败。
- audit重读源点云/GT/panoptic，复算CPU IoU和匹配基数，核验点序、所有分桶、前景/忽略/自车点、每次实际使用的采样hash、帧顺序、优化器更新数与checkpoint身份。

固定第3轮按原方案判定：处理臂最终TP至少比max(C0,F)多10，precision最多下降2个百分点，小目标最终TP不退步、小目标几何TP最多下降10；中/大目标recall、忽略区、自车点和至少5/8场景约束一起保留。原生/独立匹配的分桶差1不算收益。检查167例“离线匹配几何合格但NO_OBJECT”的训练探针是否发生类别转化，并报告每帧FP与重复候选目标边数。

新配置默认0.1保持旧目标数学行为；旧配置缺该字段时填默认值。`load_native`仍拒绝源码身份不同的精确恢复。只有显式、来源SHA256匹配的`load_warm_start`允许改变该损失字段，且不允许顺带修改架构。实验使用独立输出目录，不覆写E1或原4090环境。
